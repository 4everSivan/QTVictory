# QTVictory

**面向量化交易系统的模拟底座** —— 以真实行情与 A 股规则级撮合构建的实时前向仿真环境。
**A real-time paper-trading simulator with rule-level A-share matching, evolving from a simulation base into a personal quantitative trading system.**

> **当前状态：设计定稿，实现进行中。** 本文呈现的是目标形态与架构蓝图，功能尚未实现；各模块进度见 [当前进度](#当前进度)。

---

## 这是什么

QTVictory 用**真实行情**（腾讯/东财公开接口轮询）和**真实交易规则**（费用 / T+1 / 涨跌停 / 整手申报 / 有效申报范围）搭建一个 A 股实时前向仿真环境，供策略程序在 paper trading 中验证、对比与评估。

它的量化底座语义：

- 每个**交易员**是一个被测策略实例（strategy 模式）或手动基线（manual 模式）；
- 多交易员并行 = 多策略 A/B 对比，绩效指标（收益率 / 回撤 / 夏普 / 超额 vs 沪深300）统一口径；
- 外部量化程序以 API-first 方式接入：WS 消费行情 → 决策 → REST 下单，全部能力可程序化调用。

项目从模拟底座起步，最终演化为私人的量化交易系统（[路线图](#路线图)）。

## 设计亮点

- **A 股规则级撮合仿真**——盘口五档驱动市价单（最优五档剩余撤销 / 对手方最优）、限价单排队语义与部分成交、连续竞价 ±2% 有效申报范围、集合竞价、板块差异化申报单位（主板/创业板 100 股整数倍、科创板 ≥200 股 1 股递增）、资金/持仓冻结、T+1、涨跌停、佣金/印花税/过户费。
- **观察员-交易员体系**——系统唯一的观察员是管理员而非交易者（无账户、不下单、不入排行）；任意数量交易员由观察员全权管理，订单来源区分 `manual / operator / plan / strategy`，多策略实例的绩效天然可比。
- **API-first**——Web UI 只是后端 API 的一个客户端，不持有任何独占能力；写操作幂等（`Idempotency-Key` / `clientOrderId`）、令牌桶限速、游标分页、统一错误模型、观察员操作全量审计。为任意外部驱动程序（脚本、策略框架、智能体）预留完整机器接口。
- **交易计划引擎**——标的池 / 资金预算 / 仓位目标 / 止损止盈 / 日亏损熔断；条件单四类触发器（价格穿越、当日涨跌幅、定时、均线交叉）；策略输出须经"池内 → 预算 → 仓位 → 单笔"四道围栏过滤后才执行。

另有两个工程细节值得一提：**行情三级降级链**（腾讯 → 东财 → 内置锚点，降级时撮合自动回落固定滑点档并逐单标注 `fill_model=fallback`）；Web 控制台继承 **Nothing 设计系统**（单色灰阶即层级，红仅用于数据语义，双主题皮肤）。

## 架构

```
┌─────────────────────────── API 层 ────────────────────────────┐
│  REST (/api/*，全能力)             WebSocket (/ws 订阅式)       │
│  Auth 中间件（观察员 Key）· 限速 · 幂等 · 审计                   │
├─────────────────────────── 服务层 ────────────────────────────┤
│ MarketService   TraderService   TradingService   PlanService  │
│ MetricsService  ExportService   SessionService                 │
├─────────────────────────── 领域层 ────────────────────────────┤
│ MatchingEngine（费用/涨跌停/T+1/成本口径，纯函数）               │
│ PlanEngine（触发评估/风控钩子/约束过滤，纯函数）                  │
│ Strategies（8 策略模板，纯函数）                                 │
├─────────────────────────── 适配层 ────────────────────────────┤
│ QuotePoller(Tencent)  KlineSyncer  FallbackProvider(锚点)     │
├─────────────────────────── 持久层 ────────────────────────────┤
│ SQLite（traders/plans/entries/audit_log/klines/…，WAL）       │
└───────────────────────────────────────────────────────────────┘
```

单一事件循环串行化全部状态变更；撮合 / 计划 / 策略内核为无 I/O 纯函数，可单测。

**技术栈**：Python 3.11 · FastAPI · uvicorn · SQLite (WAL) · httpx · pydantic v2 · asyncio ｜ 前端 Vite + 纯 SVG 图表 + Nothing 设计系统双主题

## 部署形态

私人单机自部署，刻意保持简单：

- 单进程 uvicorn，默认仅监听 `127.0.0.1:8787`，不上公网；
- SQLite（WAL）单文件落库，零外部服务依赖；
- 默认免鉴权（纯私人本机定位，启动日志告警）；可选 `QTV_API_KEY` 启用观察员凭证；
- 全部行为经 `QTV_*` 环境变量配置（轮询间隔、量约束比例、分红税率、限速等）。

> 可执行的快速开始命令将在 Phase 1 首个可运行版本落地后补充。

## 关键设计决策

以下取舍均经对抗评审后拍板（完整记录：[02](docs/devel/design/02-后端设计方案.md) §6.13）：

- **观察员不直接交易**（Q1）——系统唯一观察员无账户、不下单；手动交易 = 创建 manual 模式交易员代操作。权限面干净，全部动作落审计日志。
- **空世界首启，不做演示播种**（Q2）——定位是量化底座而非演示产品；8 种策略模板仅作功能验证与绩效基线参照。
- **撮合仿真度选"规则级"而非"固定滑点"**（Q3）——盘口五档 + 真实成交量约束（单实例每 tick ≤ 真实成交量 25%，多实例共享限额池）+ 部分成交；滑点由流动性自然产生，避免穿透真实深度。固定滑点仅保留为行情降级档。
- **默认免鉴权**（Q4）——纯私人本机使用，仅监听 127.0.0.1 并日志告警；`QTV_API_KEY` 可选启用。不为单人场景引入账户体系。
- **事件通道 = WS 主路 + REST 轮询兜底，不做 Webhook**（Q6）——纯本机部署下外部程序主动连 WS 最自然；反向回调的注册/重试/签名复杂度无收益。

## 免责声明与已知边界

**免责声明**：本项目仅供学习与技术研究，不构成任何投资建议；模拟交易结果不代表真实市场表现。行情数据来自腾讯/东方财富的公开接口，仅供模拟用途。

**已知边界**（设计内接受的简化）：

- 分钟线历史自部署日起逐日累积，历史分钟不回补（免费源分钟历史深度有限且质量差）；
- 现金分红按统一税率计税（默认 10%，可配置免税），不做差异化持有期税率（>1年免 / 1月–1年10% / <1月20%）；
- 行情为轮询快照级（约 3s），无 Level-1 逐笔订阅；tick 快照不留档。
