## 1. 简介与隔离设计原则

在量化交易系统的开发与验证过程中，频繁运行单元测试、接口集成测试、E2E 几何校验以及脏数据注水实验，极易对本地长期运行的生产账本造成污染，或因默认端口冲突导致服务冲突崩溃。

本指南用于指导搭建一个与生产/开发主环境**严格隔离的独立测试环境**。核心设计原则如下：

1. **绝对隔离原则**：测试环境运行产生的**所有临时文档、数据库、日志、框架缓存与测试产物，全部收拢在项目根目录的 `local/` 目录下**。严禁向源码树（`backend/`、`frontend/`）扩散脏文件。
2. **生产环境最大复用原则**：若宿主机上已存在生产或常规开发虚拟环境（如 `backend/.venv`），直接复用该 Python 环境，无需重复下载巨量依赖包与编译轮子；仅当宿主机无可用环境时，才在 `local/.venv` 下独立新建测试虚拟环境。
3. **长期保留与按需清理**：测试环境默认**长期保留**，不随单次测试结束而销毁；`local/` 目录已被全局 Git 忽略（`.gitignore`），长期留存不会污染仓库。仅当需要彻底重置或释放磁盘时，才按第 8 章分级方案清理；届时一键删除 `local/` 即可完全销毁，不留任何磁盘垃圾。

## 2. local/ 目录规范与文件全分类

测试环境的所有运行时输出严格按照以下子目录层级归类：

```
local/
├── .venv/                   # [运行环境] 独立测试虚拟环境（仅无现成环境时建置）
├── deployment-report.md     # [部署验收] 部署验收单：现实采集 + 维护命令 + 人工签署
├── data/                    # [持久账本] 测试专用 SQLite 数据库与 WAL 日志
│   ├── qtvictory_test.db    # 测试库主数据文件
│   ├── qtvictory_test.db-wal# SQLite 预写日志（Write-Ahead Log）
│   └── qtvictory_test.db-shm# SQLite 共享内存索引
├── logs/                    # [运行日志] 各服务与测试命令重定向日志
│   ├── backend-test.log     # 测试后端 Uvicorn 运行日志
│   ├── pytest.log           # 后端 pytest 详细测试日志
│   ├── vitest.log           # 前端单测运行日志
│   └── e2e.log              # Playwright E2E 几何实测日志
├── cache/                   # [框架缓存] 编译、测试框架与覆盖率缓存
│   ├── .pytest_cache/       # pytest 步进与失败用例节点缓存
│   ├── vitest/              # Vitest 模块热转换缓存
│   └── coverage/            # 单元测试覆盖率报告与中间产物
├── test-results/            # [测试产物] 测试截图、追踪链路与快照
│   ├── screenshots/         # E2E 校验失败或比对截屏
│   └── traces/              # Playwright 调试追踪链路压缩包
└── tmp/                     # [临时交换] 临时导出流水、对账中间文件
    ├── trader_export_*.csv  # 交易流水导出 CSV 临时文件
    └── order_dump_*.json    # 委托明细快照 JSON 临时文件
```

### 2.1 运行时产生文件全景分类表

| 类别 | 相对路径 / 模式 | 产生源头 | 产生时机 | 生命周期 | 重定向 / 指定方式 | 清理级别 |
|---|---|---|---|---|---|---|
| **虚拟环境** | `local/.venv/` | `uv` / `python` | 宿主机无可用 Python 环境时首次建置 | 长期保留 | `uv venv local/.venv` | 销毁重建 |
| **测试数据库** | `local/data/qtvictory_test.db*` | SQLite 内核 | 启动测试后端或执行持久化集成测试 | 跨测试保留 | 环境变量 `QTV_DB=local/data/qtvictory_test.db` | 数据重置 |
| **部署验收单** | `local/deployment-report.md` | 部署采集脚本（§5 第四步） | 每次部署或环境信息变更后 | 随环境长期保留 | 脚本自动生成 | 仅级别 C 随环境销毁 |
| **服务运行日志** | `local/logs/backend-test.log` | FastAPI / Uvicorn | 启动测试后端服务实例 | 随服务进程追加 | 启动重定向 `> local/logs/backend-test.log 2>&1` | 日常清理 |
| **测试执行日志** | `local/logs/pytest.log` | pytest | 执行 `pytest backend/tests` | 每次执行覆写/追加 | 参数 `--log-file=local/logs/pytest.log` | 日常清理 |
| **前端单测日志** | `local/logs/vitest.log` | vitest | 执行前端 `npm test` | 每次执行覆写/追加 | 参数 `--outputFile=../local/logs/vitest.log` | 日常清理 |
| **E2E 实测日志** | `local/logs/e2e.log` | Playwright E2E 脚本 | 执行 `node scripts/e2e.mjs` | 每次执行覆写 | 重定向 `> local/logs/e2e.log 2>&1` | 日常清理 |
| **Pytest 缓存** | `local/cache/.pytest_cache/` | pytest 框架 | pytest 运行自动化用例 | 长期加速使用 | 参数 `-o cache_dir=local/cache/.pytest_cache` | 缓存重置 |
| **覆盖率报告** | `local/cache/coverage/` | coverage / vitest | 运行带覆盖率统计的测试命令 | 每次报告更新 | 配置输出目录至 `local/cache/coverage` | 缓存重置 |
| **E2E 失败截图** | `local/test-results/screenshots/` | Playwright 浏览器 | 几何或断言校验失败自动抓取 | 故障排查期 | 脚本配置截图保存路径 | 测试收口清理 |
| **临时导出文件** | `local/tmp/trader_*.csv` | 观察员控制台 / REST API | 触发数据导出或备份端点 | 阅后即弃 | 脚本或导出参数重定向至 `local/tmp/` | 随时可清 |

为兼顾**极速启动**与**环境纯净**，按以下流程决定使用何种虚拟环境：

```
                    ┌─────────────────────────┐
                    │ 检查当前是否已激活环境   │
                    │ ($VIRTUAL_ENV 非空?)    │
                    └───────────┬─────────────┘
                                │ 是
                 ┌──────────────┴──────────────┐ 否
                 │                             │
                 ▼                             ▼
        ┌──────────────────┐        ┌─────────────────────────┐
        │ 直接复用当前环境 │        │ 检查 backend/.venv 是否 │
        │   (无需新装依赖) │        │ 存在且可用              │
        └──────────────────┘        └───────────┬─────────────┘
                                                │ 是
                                 ┌──────────────┴──────────────┐ 否
                                 │                             │
                                 ▼                             ▼
                        ┌──────────────────┐        ┌─────────────────────────┐
                        │ 激活 backend/.venv│        │ 检查 local/.venv 是否   │
                        │ 直接复用生产依赖 │        │ 存在                    │
                        └──────────────────┘        └───────────┬─────────────┘
                                                                │ 是
                                                 ┌──────────────┴──────────────┐ 否
                                                 │                             │
                                                 ▼                             ▼
                                        ┌──────────────────┐        ┌─────────────────────────┐
                                        │ 激活 local/.venv │        │ 在 local/.venv 独立建置 │
                                        │   已有测试环境   │        │ 并安装 backend[dev] 依赖│
                                        └──────────────────┘        └─────────────────────────┘
```

### 3.1 自动化环境探测脚本

在终端中执行以下脚本片段，即可智能复用现有环境或就地建置：

```bash
# 1. 确保 local 规范目录已建好
mkdir -p local/{data,logs,cache,test-results,tmp}

# 2. 智能探测与复用虚拟环境
if [ -n "$VIRTUAL_ENV" ]; then
    echo "✓ [复用] 当前已激活虚拟环境: $VIRTUAL_ENV"
elif [ -d "backend/.venv" ]; then
    echo "✓ [复用] 发现主生产/开发环境 backend/.venv，直接激活复用。"
    source backend/.venv/bin/activate
elif [ -d "local/.venv" ]; then
    echo "✓ [复用] 发现已有测试环境 local/.venv，激活复用。"
    source local/.venv/bin/activate
else
    echo "ℹ [建置] 未检测到现成环境，在 local/.venv 创建独立测试环境..."
    uv venv local/.venv || python3 -m venv local/.venv
    source local/.venv/bin/activate
    echo "ℹ 正在安装后端测试依赖..."
    uv pip install -e "backend[dev]" || pip install -e "backend[dev]"
fi
```

### 3.2 前端依赖准备

前端依赖采用共享的 `frontend/node_modules`，执行前端测试或构建前确保已安装：

```bash
cd frontend
npm install
cd ..
```

## 4. 测试环境变量配置

测试环境必须通过环境变量重定向数据库路径与监听端口，避免与宿主机上的正式服务（默认 `127.0.0.1:8787` 和 `backend/data/qtvictory.db`）发生资源竞争。

### 4.1 生产与测试配置对比

| 配置项 | 生产/单机默认值 | 测试环境推荐值 | 隔离意义 |
|---|---|---|---|
| `QTV_PORT` | `8787` | **`8788`**（或 `18787`） | 端口隔离，允许生产与测试实例同时驻留运行 |
| `QTV_DB` | `data/qtvictory.db` | **`local/data/qtvictory_test.db`** | 数据库隔离，保证测试写盘不碰生产数据 |
| `QTV_CORS` | `http://localhost:4312` | **`http://localhost:4313`**（或保持 `4312`） | 避免跨域策略报错 |
| `QTV_POLL_SEC` | `3` | **`1`**（或使用测试离线注水） | 加快行情轮询节拍以便快速触发测试逻辑 |
| `QTV_API_KEY` | `""`（空） | 按需注入（如 `"test-secret-key"`） | 校验鉴权中间件时开启 |

### 4.2 快捷环境变量注入

可将测试环境变量导出至当前 Shell 会话，或在启动命令前单行传入：

```bash
# 导出测试环境专用环境变量（在仓库根目录执行）
export QTV_PORT=8788
export QTV_DB=local/data/qtvictory_test.db
export QTV_CORS="http://localhost:4313"
```

## 5. 测试环境部署与启动步骤

部署流程共四步。**以第四步生成《部署验收单》并完成人工签署为部署完成标志**——验收单必须落在 `local/` 目录下，且其中的维护命令必须基于本次部署的现实采集值（实际端口、前端入口地址、数据库与日志路径），禁止照抄本指南中的示例值。

### 第一步：初始化目录层级
```bash
mkdir -p local/{data,logs,cache,test-results,tmp}
```

### 第二步：启动独立测试后端
在仓库根目录执行，日志定向输出至 `local/logs/backend-test.log`：

```bash
# 后台启动测试后端实例
PYTHONPATH=backend QTV_PORT=8788 QTV_DB=local/data/qtvictory_test.db \
    python -m app.main > local/logs/backend-test.log 2>&1 &

# 记录进程 PID（便于后续停止）
TEST_BACKEND_PID=$!
echo "测试后端已在后台启动，PID: $TEST_BACKEND_PID，端口: 8788"
```

### 第三步：健康检查与连通性验证
```bash
# 等待 1 秒待服务就绪
sleep 1
curl -s http://127.0.0.1:8788/api/session | jq .
```
若返回 `{"date":"...","status":"OPEN","phase":"CONTINUOUS"}`，表示测试环境后端部署成功，且测试数据库已在 `local/data/qtvictory_test.db` 自动初始化。

### 第四步：生成部署验收单（人工验收依据）

部署完成后**必须**执行以下采集脚本。脚本先采集本次部署的现实值（端口、前端入口地址、数据库路径、虚拟环境、健康检查结果），再生成 `local/deployment-report.md`——文档内含**已绑定现实值的维护命令**（可直接复制执行）与人工验收签署区。前端访问入口以完整 URL 写入表格，支持在终端 / 编辑器中 Cmd+点击直接在浏览器打开：

````bash
# ---- 采集本次部署现实值 ----
PORT=${QTV_PORT:-8788}
DB=${QTV_DB:-local/data/qtvictory_test.db}
VENV_PATH=${VIRTUAL_ENV:-未激活}
FRONTEND_URL=${QTV_CORS:-http://localhost:4312}
REPORT=local/deployment-report.md

# ---- 生成部署验收单 ----
{
  echo "# QTVictory 测试环境部署验收单"
  echo
  echo "## 一、部署现实采集"
  echo
  echo "| 项目 | 采集值 |"
  echo "|---|---|"
  echo "| 生成时间 | $(date '+%Y-%m-%d %H:%M:%S') |"
  echo "| Git 分支 / 提交 | $(git branch --show-current) / $(git rev-parse --short HEAD) |"
  echo "| 操作系统 | $(uname -srm) |"
  echo "| Python | $(python --version 2>&1) |"
  echo "| 虚拟环境 | $VENV_PATH |"
  echo "| Node / npm | $(node --version 2>&1) / $(npm --version 2>&1) |"
  echo "| 前端访问入口（Cmd+点击打开） | $FRONTEND_URL |"
  echo "| 后端接口 | http://127.0.0.1:$PORT/api |"
  echo "| 监听端口 | $PORT |"
  echo "| 数据库 | $DB |"
  echo "| 后端健康检查 | $(curl -s http://127.0.0.1:$PORT/api/session || echo 'UNREACHABLE') |"
  echo "| 后端日志 | local/logs/backend-test.log |"
  echo
  echo "## 二、维护命令（基于本次部署现实值，可直接复制执行）"
  echo
  echo "### 进程管理"
  echo '```bash'
  echo "# 查看后端进程与端口占用"
  echo "lsof -i:$PORT"
  echo "# 停止后端（按端口定位：PID 随重启变化，不写死）"
  echo "lsof -ti:$PORT | xargs kill"
  echo "# 重启后端（先停后启）"
  echo "lsof -ti:$PORT | xargs kill; sleep 1"
  echo "PYTHONPATH=backend QTV_PORT=$PORT QTV_DB=$DB \\"
  echo "    python -m app.main > local/logs/backend-test.log 2>&1 &"
  echo '```'
  echo
  echo "### 健康检查"
  echo '```bash'
  echo "curl -s http://127.0.0.1:$PORT/api/session | jq ."
  echo "# 浏览器打开前端（macOS open；或 Cmd+点击上方表格中的入口链接）"
  echo "open $FRONTEND_URL"
  echo '```'
  echo
  echo "### 日志排查"
  echo '```bash'
  echo "tail -f local/logs/backend-test.log"
  echo 'grep -E "(ERROR|Traceback)" local/logs/backend-test.log'
  echo '```'
  echo
  echo "### 数据库维护"
  echo '```bash'
  echo "sqlite3 $DB \".tables\""
  echo "sqlite3 $DB \"SELECT id, name, mode, cash FROM traders;\""
  echo "sqlite3 $DB \".backup 'local/data/qtvictory_test_backup.db'\""
  echo '```'
  echo
  echo "### 依赖与环境"
  echo '```bash'
  if [ "$VENV_PATH" != "未激活" ]; then
    echo "source $VENV_PATH/bin/activate"
  else
    echo "# 当前无已激活虚拟环境，复用或建置见指南第 3 章"
  fi
  echo 'uv pip install -e "backend[dev]" || pip install -e "backend[dev]"'
  echo '```'
  echo
  echo "## 三、人工验收签署"
  echo
  echo "| 验收人 | 验收日期 | 验收结论 | 备注 |"
  echo "|---|---|---|---|"
  echo "|  |  | 通过 / 不通过 |  |"
} > "$REPORT"
echo "部署验收单已生成: $REPORT ，请人工核验采集值并填写签署区。"
````

验收单随测试环境长期保留（已 gitignore）。**环境信息变更后（换端口、换前端入口、重建虚拟环境）必须重新执行本步覆盖更新**，确保验收单中的维护命令始终与现实一致。

## 6. 自动化测试套件执行（产物全量收拢）

所有的自动化测试命令在执行时，通过参数严格将缓存与日志导流到 `local/` 目录：

### 6.1 后端全量测试 (pytest)
通过 `-o cache_dir` 将 `.pytest_cache` 锁在 `local/cache/`：

```bash
pytest backend/tests \
    -o cache_dir=local/cache/.pytest_cache \
    --log-file=local/logs/pytest.log \
    -q
```
*执行后：源码根目录与 `backend/` 目录下不会产生任何 `.pytest_cache` 文件夹。*

### 6.2 前端单元与组件测试 (Vitest)
运行 180 项前端组件与设计系统单测：

```bash
cd frontend
npm test -- --outputFile=../local/logs/vitest.log
cd ..
```

### 6.3 浏览器端到端 E2E 几何与交互校验 (Playwright)
运行 37 项浏览器端到端 E2E 几何与交互校验（含三态主题、自选股增删联想、四周期图表与主副图指标切换）：

```bash
# 需保证测试后端（8788 或 8787）正常运行
node frontend/scripts/e2e.mjs > local/logs/e2e.log 2>&1
```

### 6.4 文档治理状态自检 (scripts/jev_workflow_check.py)
在收口或合入主干前，按 AGENTS.md 红线 7 执行治理流状态自检，验证双向互链闭环与零沉淀纪律：

```bash
# 联网语义自检（调用 Jev 模型）
python3 scripts/jev_workflow_check.py

# 或离线免模型仅采集核验（执行代码侧硬判门禁）
python3 scripts/jev_workflow_check.py --offline
```

## 8. 一键复位与环境清理

测试环境默认长期保留，以下三级清理方案**仅在需要时按需执行**，并非每次测试后的常规收尾步骤。所有操作均限定在 `local/` 范围内，绝对安全：

### 级别 A：清空测试日志与中间缓存（保留数据库与虚拟环境）
适用于多次回归测试之间需要重置运行状态与日志时：
```bash
rm -rf local/logs/* local/cache/* local/test-results/* local/tmp/*
mkdir -p local/{logs,cache,test-results,tmp}
```

### 级别 B：重置测试数据库（恢复初始空世界）
适用于需要清除脏交易数据、从初始账本重新注水时，保留虚拟环境与日志：
```bash
# 先终止测试后端进程
pkill -f "QTV_PORT=8788" || kill $TEST_BACKEND_PID 2>/dev/null

# 移除测试数据库与 WAL 文件
rm -f local/data/qtvictory_test.db*
```

## 9. 常见问题 (FAQ)

### Q1: 测试后端启动时提示 `Address already in use: 8788`？
**解答**：说明上一次测试的后台进程尚未终止。执行以下命令释放：
```bash
lsof -ti:8788 | xargs kill -9 2>/dev/null
```

### Q2: 生产环境有代码更新时，复用的虚拟环境如何保持最新？
**解答**：若复用了 `backend/.venv` 或已有环境，由于安装时采用了 `uv pip install -e "backend[dev]"`（Editable 源码可编辑安装模式），后端代码的任何更改均**实时生效**，无需重新安装依赖。若新增了第三方库，仅需执行 `uv pip install -e "backend[dev]"` 增量更新即可。

### Q3: 为什么 pytest 执行后根目录还是多出了 `__pycache__`？
**解答**：Python 在加载 `.py` 模块时默认会在同级生成 `__pycache__`。可在执行测试前设置环境变量阻止字节码写入磁盘：
```bash
PYTHONDONTWRITEBYTECODE=1 pytest backend/tests -o cache_dir=local/cache/.pytest_cache
```
或执行一键清理：
```bash
find backend -type d -name "__pycache__" -exec rm -rf {} +
```
