## 1. 简介

**QTVictory** 是专为个人量化开发者设计的 A 股实时前向仿真（Paper Trading）模拟交易系统。

### 1.1 部署形态与定位
- **私人单机自部署**：默认仅监听本地回环地址 `127.0.0.1`，不暴露公网，无需多租户与复杂用户鉴权系统。
- **极简无外置依赖架构**：后端采用单进程异步 FastAPI + Uvicorn 架构，数据单文件落入本地 SQLite（WAL 模式），无外部数据库或消息队列（如 Redis/MySQL/Kafka）依赖。
- **前后端解耦**：后端提供全能力 RESTful API 与 WebSocket 实时双向推送通道；前端为基于 React 18 + TypeScript + Vite 构建的静态单页控制台，通过 HTTP/WS 与后端通信。

```
┌──────────────────────────────────────────────────────────────┐
│                    本机客户端 (Browser / API)                 │
│         Web 控制台: http://localhost:4312                     │
│         OpenAPI 文档: http://127.0.0.1:8787/api/docs         │
└──────────────────────────────┬───────────────────────────────┘
                               │ HTTP / WebSocket
┌──────────────────────────────▼───────────────────────────────┐
│              QTVictory 后端服务 (127.0.0.1:8787)              │
│  FastAPI · 纯函数撮合内核 · 计划引擎 · 腾讯行情适配器          │
└──────────────────────────────┬───────────────────────────────┘
                               │ 单文件原子读写
┌──────────────────────────────▼───────────────────────────────┐
│          SQLite WAL 模式数据库 (data/qtvictory.db)           │
└──────────────────────────────────────────────────────────────┘
```

## 3. 配置文件与环境变量

QTVictory 采用现代化的**环境变量注入机制**，无繁杂的外部 XML/YAML 配置文件，所有行为均由环境变量控制，开箱即具备合理默认值。

### 3.1 后端环境变量全表 (`QTV_*`)
后端环境变量在启动前由系统环境或命令行注入，具体配置项如下（定义见 [`backend/app/config.py`](../../backend/app/config.py)）：

| 变量名 | 默认值 | 类型 | 详细说明 |
|---|---|---|---|
| `QTV_PORT` | `8787` | 整数 | 后端服务监听端口（范围 1–65535） |
| `QTV_DB` | `data/qtvictory.db` | 路径 | SQLite 数据库存储路径（自动开启 WAL 模式） |
| `QTV_POLL_SEC` | `3` | 整数 | 连续竞价期间腾讯公开行情轮询间隔（秒） |
| `QTV_API_KEY` | `""`（空） | 字符串 | 观察员安全凭证；为空时**仅限本机免鉴权**，非空时全端点校验 `X-API-Key` |
| `QTV_PUBLIC_READ` | `false` | 布尔值 | 启用鉴权时，是否放行 GET 只读端点供外部匿名监视 |
| `QTV_RATE_LIMIT` | `20` | 整数 | 令牌桶限流上限（请求/秒） |
| `QTV_VOLUME_PARTICIPATION` | `0.25` | 浮点数 | 单标的每 tick 成交量占市场真实成交量比例上限（25% 流动性约束） |
| `QTV_DIVIDEND_TAX` | `0.10` | 浮点数 | 现金分红除息时代扣统一税率（默认 10%） |
| `QTV_MAX_TRADERS` | `64` | 整数 | 系统允许创建的最大交易员实例数 |
| `QTV_KLINE_DEPTH` | `800` | 整数 | 日K引导/校准重拉深度（根数，上限 800；单源失败回落 320） |
| `QTV_CORS` | `http://localhost:4312` | URL | 跨域资源共享（CORS）允许的前端来源地址 |

### 3.2 前端环境变量 (`frontend/.env`)
前端配置通过 Vite 编译注入。在 `frontend/` 目录下复制配置模板：

```bash
cd frontend
cp .env.example .env
```

`.env` 文件内容说明：
```ini
# 后端 REST API 访问根基地址
VITE_API_BASE=http://127.0.0.1:8787/api

# 若后端配置了 QTV_API_KEY，在此填入相同凭证；若后端默认免鉴权，保持为空
VITE_API_KEY=
```

## 4. 部署与启动流程

### 4.1 方案 A：开发者与联调模式（推荐首次体验）

此模式下前端支持代码热更新（HMR），适合快速体验与调试策略。

#### 第一步：启动后端服务
```bash
cd backend

# 1. 创建 Python 虚拟环境（推荐使用 uv，亦可使用 python3 -m venv .venv）
uv venv
source .venv/bin/activate

# 2. 安装后端依赖
uv pip install -e ".[dev]"

# 3. 启动后端（默认监听 127.0.0.1:8787）
python -m app.main
```
*启动成功终端回显提示：*
```text
INFO:     Started server process
INFO:     Waiting for application startup.
INFO:     Application startup complete.
INFO:     Uvicorn running on http://127.0.0.1:8787 (Press CTRL+C to quit)
```

#### 第二步：启动前端控制台
打开新的终端窗口：
```bash
cd frontend

# 1. 安装前端依赖
npm install

# 2. 启动 Vite 开发服务器
npm run dev
```
*启动成功终端回显提示：*
```text
  VITE v8.x.x  ready in 180 ms

  ➜  Local:   http://localhost:4312/
```

在浏览器中打开 **`http://localhost:4312`** 即可进入 QTVictory 观察员控制台。

---

### 4.2 方案 B：生产构建与静态部署模式（适合长期平稳运行）

此模式将前端构建为高压缩的静态网页资源，通过本地预览服务或 Nginx 托管，资源占用最小。

#### 第一步：编译前端静态产物
```bash
cd frontend
npm install
npm run build         # 输出至 frontend/dist/
```

#### 第二步：托管前端与运行后端
可通过 Vite 内置的轻量 preview 服务托管前端，亦可使用任意静态服务器：
```bash
# 方式 1：使用 vite preview 托管前端（端口 4312）
cd frontend
npm run preview

# 方式 2：使用 Python 内置 http 服务托管（备用）
cd frontend/dist
python3 -m http.server 4312 --bind 127.0.0.1
```

同时按照 4.1 第一步在后台保持后端 `python -m app.main` 运行。

## 5. 日常使用

### 5.1 观察员控制台核心功能
1. **空世界首发态**：首次启动后，系统自动初始化全局唯一观察员。顶栏会显示无交易员状态，点击“创建交易员”即可开立首个账户。
2. **多模式交易员体系**：
   - **Manual 模式**：用于人工手动测试交易逻辑；
   - **Strategy 模式**：挂载系统内置的 8 大量化策略模板（网格交易、双均线、MACD、布林带等）自动生成买卖信号；
   - **Plan 模式**：通过交易计划执行条件单。
3. **计划引擎与条件单监控**：
   - 支持设置 4 类触发器（价格穿越、涨跌幅、定时触发、均线交叉）；
   - 触发时自动经过标的池、预算与仓位四道风控围栏。
4. **纯 SVG 高性能四周期图表与三态主题**：
   - 支持在分时走势图、日K、周K、月K线图与净值走势图之间自由切换；
   - 顶栏第二胶丸组紧随月K提供 MA/EMA/BOLL 主图均线叠加，沉底对称槽位支持 VOL/MACD/RSI/KDJ 副图指标切换；
   - 顶栏一键在 Nothing Dark（深色）、Standard Light（浅色）与 System（跟随系统）三态主题间无缝切换与持久化。
5. **自选股编辑与智能联想**：
   - 支持自选股抽屉列表维护，提供实时名称/拼音/代码联想搜索添加、置顶与删除，具备本地引用码回落防丢机制。
6. **数据导出与对账**：
   - 底部 Dock 栏可一键导出当前交易员的完整委托、成交流水为 CSV 或 JSON 格式。

### 5.2 数据备份与持久化保障
QTVictory 的所有核心账本均持久化在 SQLite 中（默认位于 `backend/data/` 目录）。
由于 SQLite 处于 **WAL (Write-Ahead Logging)** 模式，备份时请遵循以下规则之一：

- **冷备份**：停止后端服务后，直接复制 `backend/data/qtvictory.db` 文件。
- **在线热备份**：后端运行期间，使用 SQLite 专用备份命令：
  ```bash
  sqlite3 backend/data/qtvictory.db ".backup 'backend/data/qtvictory_backup.db'"
  ```

**例行保护建议（2026-09-18 对抗评审裁决：数据是策略评估资产，做但不立项）**：

1. **日级快照**：每日收盘日切完成后做一次热备份，按日期滚动保留最近 30 份，例如 crontab：
   ```bash
   30 16 * * 1-5  sqlite3 ~/QTVictory/backend/data/qtvictory.db ".backup '~/QTVictory/local/backups/qtvictory_$(date +\%Y\%m\%d).db'" \
     && ls -1t ~/QTVictory/local/backups/qtvictory_*.db | tail -n +31 | xargs rm -f
   ```
   备份产物统一收拢 `local/backups/`（符合测试/运维产物 gitignore 红线）。
2. **日K 缺口体检**：长运行实例如怀疑历史 K 线缺口（停机跨换日、上游故障窗口），可抽查库存深度与末根日期：
   ```bash
   sqlite3 backend/data/qtvictory.db \
     "SELECT code, COUNT(*), MAX(date) FROM klines GROUP BY code ORDER BY 2 LIMIT 10;"
   ```
   缺口自愈依赖日切关注集重拉（C014）与校准重拉（02 §3.11），无需手工修补；持续异常再上报登记。

## 6. 卸载与清理

根据不同需求，系统支持**数据重置**、**纯净卸载**与**系统级全局清理**三种级别：

### 6.1 停止服务
直接在运行中的终端按下 `Ctrl + C`，或通过进程名查找终止：
```bash
pkill -f "app.main"
pkill -f "vite"
```

### 6.2 级别 1：重置账本数据（回到空世界首启态）
如需清空所有模拟交易流水、重置交易员与行情历史缓存，只需删除数据库文件：
```bash
rm -f backend/data/qtvictory.db*
```
重启后端后，系统将自动重新建表并回到初始空世界。

### 6.3 级别 2：工作区完全卸载（还原纯源码）
清理所有本地编译产物、Python 虚拟环境与 node_modules：
```bash
# 清理后端运行时与虚拟环境
rm -rf backend/.venv backend/data/qtvictory.db* backend/.pytest_cache
find backend -type d -name "__pycache__" -exec rm -rf {} +

# 清理前端依赖包与编译输出
rm -rf frontend/node_modules frontend/dist frontend/*.tsbuildinfo frontend/coverage
```

### 6.4 级别 3：系统级磁盘彻底释放（深度清理）
若不再使用本项目，可彻底清理包管理器下载缓存与 Playwright 无头 Chromium 二进制镜像（释放 **~2 GB+** 磁盘空间）：
```bash
# 彻底移除 Playwright 下载的 Chromium 浏览器运行时 (~563MB)
rm -rf ~/Library/Caches/ms-playwright

# 清除 uv 与 npm 全局包缓存 (~1.3GB)
uv cache clean
npm cache clean --force
```
更深入的缓存明细分类说明详见：[01-环境缓存与依赖清理指南](../devel/env/01-环境缓存与依赖清理指南.md)。

## 7. 常见问题排障 (FAQ)

### Q1: 启动后端时提示端口 8787 被占用怎么办？
**解答**：通过自定义环境变量更改监听端口：
```bash
QTV_PORT=8788 python -m app.main
```
同时需同步更新 `frontend/.env` 中的 `VITE_API_BASE=http://127.0.0.1:8788/api` 并重启前端。

### Q2: 盘口或顶栏显示“已降级 (DEGRADED)”是什么原因？
**解答**：这属于系统正常的高可用降级保护机制。QTVictory 采用四级行情降级自愈链（腾讯主源 https/http 自动回退 → 新浪主源 https+Referer 防盗链透传 → 东财备选 → 内置基准锚点 Anchor）。当本机网络代理、防火墙阻断外网行情或非交易时段接口无响应时，撮合引擎会自动平滑回落至 `fallback` 锚点模式并逐笔标记订单，保障下单撮合全流程不崩溃、不白屏。

### Q3: 访问控制台提示 CORS 跨域错误？
**解答**：后端默认允许的来源是 `http://localhost:4312`。如果前端运行在其他端口（如 5173），请启动后端时指定放行地址：
```bash
QTV_CORS=http://localhost:5173 python -m app.main
```

### Q4: 如何开启安全鉴权防止未授权访问？
**解答**：在启动后端时设置安全凭证：
```bash
QTV_API_KEY="my-secret-token" python -m app.main
```
并在前端 `frontend/.env` 中配置 `VITE_API_KEY=my-secret-token`。启用后所有 REST 端点与 WebSocket 握手均会执行常量时间密钥校验。
