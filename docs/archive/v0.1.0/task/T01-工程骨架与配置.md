## 1. 目标与范围

建立 `backend/` 工程骨架：目录结构、依赖锁定、`QTV_*` 配置加载、FastAPI 应用装配、pytest 测试基建、单一事件循环串行化基座。本任务不含任何业务功能。

## 2. 任务明细

### T01-1 仓库与依赖
- **内容**：按 02 §4.5 建立 `backend/` 目录（`app/main.py`、`api/`、`services/`、`domain/`、`adapters/`、`models/`、`store/`、`config.py`、`tests/`、`migrations/`）；`pyproject.toml` 锁定依赖：Python 3.11、FastAPI、uvicorn、httpx、pydantic v2（§4.2）。
- **交付物**：可安装的包骨架 + 依赖清单。
- **验收标准**：目录与 §4.5 逐项一致；`pip install -e backend` 成功；Python 3.11 版本检查通过。

### T01-2 配置模块（config.py）
- **内容**：实现 §6.10 全部 10 项环境变量：`QTV_PORT / QTV_DB / QTV_POLL_SEC / QTV_API_KEY / QTV_PUBLIC_READ / QTV_RATE_LIMIT / QTV_VOLUME_PARTICIPATION / QTV_DIVIDEND_TAX / QTV_MAX_TRADERS / QTV_CORS`；基于 pydantic-settings，默认值与 §6.10 表一致。
- **交付物**：`config.py` + 默认值单测。
- **验收标准**：每项可注入覆盖；非法值（负数端口、>1 的比例等）启动即报错；单测覆盖默认值表全项。

### T01-3 应用装配（main.py）
- **内容**：FastAPI 应用工厂；CORS 白名单取 `QTV_CORS`（默认 `http://localhost:4312`）；`GET /health` 端点；uvicorn 入口（host `127.0.0.1`，port `QTV_PORT`，§4.6）；启动日志框架（"无鉴权模式"告警的实际判定逻辑在 T09-4，此处预留日志钩子）。
- **交付物**：可启动的空应用。
- **验收标准**：启动后 `/health` 返回 200；来自白名单外源的 CORS 拒绝；端口/地址随配置生效。

### T01-4 测试基建
- **内容**：pytest + pytest-asyncio；`tests/` 三层约定（`unit/` 纯函数、`service/` 服务层、`integration/` 集成）；conftest 提供临时数据库与事件循环 fixture；统一测试运行入口（make/script）。
- **交付物**：测试目录 + 示例用例。
- **验收标准**：示例测试三层各至少一条全绿。

### T01-5 事件循环串行化基座
- **内容**：提供 asyncio 单写者调度原语（串行队列或等价机制），全部状态变更经此串行执行（§2.3 一致性、§4.4 同一事件循环）。
- **交付物**：`app/` 内可复用的调度原语 + 接口文档（docstring）。
- **验收标准**：并发提交 N 个状态变更时严格按到达顺序执行的单测；后续服务（T05/T07/T11）接入方式明确。

### T01-6 启动装配序（lifespan）
- **内容**：lifespan 编排框架与扩展点：迁移执行（T02）→ 观察员初始化（预留 T09-3）→ 行情启动（预留 T06）→ 日切检查（预留 T08）；各阶段顺序固定、失败即中止启动。
- **交付物**：lifespan 编排代码 + 阶段顺序单测。
- **验收标准**：阶段顺序断言通过；任一阶段异常时应用不进入服务状态。
