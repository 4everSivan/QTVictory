## 1. 目标与范围

下单校验链编排、撮合引擎的运行时集成、订单生命周期与撤单、幂等兜底（02 §3.6）。本任务是 [T03 纯函数内核](T03-撮合引擎.md)的运行时壳：取 MarketBus 数据、调内核、把成交/状态/冻结变更落库。

## 2. 任务明细

### T07-1 下单校验链编排
- **内容**：按 §3.6 顺序编排：会话状态 → 交易员状态 → 停牌 → 申报单位 → 有效申报价格范围 → 市价单类型 → 资金/持仓冻结 → 可用资金/可卖（T+1 且扣冻结）→ 计划约束（检查点由 [T11-5](T11-计划服务接入.md) 接入）→ 生成订单（`origin = manual | operator | plan | strategy`，§3.1）。
- **交付物**：校验链服务 + 拒单码映射。
- **验收标准**：§5.4 逐码触发用例：`LOT_SIZE / PRICE_BAND（双区间 details）/ INSUFFICIENT_FUNDS / T1_LOCKED / SESSION_CLOSED / STALE_QUOTE / TRADER_CLOSED / PLAN_CONSTRAINT / PLAN_PAUSED`；四类 origin 均经同一链路。

### T07-2 撮合 tick 集成
- **内容**：每 tick 从 MarketBus 取快照与 ΔV → 调 MatchingEngine（含限额池维护：多交易员共享、按到达顺序）→ 成交/订单状态/冻结变更落库；`trades.order_id` 非唯一（一单多笔）；编排顺序对齐 §4.4（PlanEngine.tick 与 MatchingEngine.tick 同串行基座）。
- **交付物**：tick 集成编排 + 限额池运行时。
- **验收标准**：限价单跨 tick 分批部分成交、市价单五档加权的端到端落库一致；限额池多交易员竞争集成用例。

### T07-3 撤单与解冻
- **内容**：可撤窗口（连续竞价与 9:15–9:20；9:20–9:25 与收盘后禁撤）；撤单解冻（部分成交按剩余量）；级联撤单（计划删除级联，供 T11 调用）；日终撤单归 [T08](T08-会话服务与日切.md)。
- **交付物**：撤单服务。
- **验收标准**：窗口内外行为断言；部分成交后撤单的冻结回收金额精确。

### T07-4 幂等与 clientOrderId
- **内容**：`clientOrderId` 查重（与 [T09-5](T09-REST与鉴权幂等.md) 幂等中间件配合，本层为服务端兜底）；重复提交返回首次结果；键冲突且请求体不一致 → `DUPLICATE_REQUEST`。
- **交付物**：订单幂等逻辑。
- **验收标准**：并发重复提交仅生成一单；重放返回首次结果。

### T07-5 错误模型触发点
- **内容**：定义 §5.4 码表各码在服务层的触发位置与 `details` 内容契约（如 `PRICE_BAND` 返回涨跌停与 ±2% 两个区间、`STALE_QUOTE` 返回行情时间戳）；HTTP 层封装归 T09。
- **交付物**：错误触发点清单 + details 契约。
- **验收标准**：错误响应结构与 §5.4 逐项一致（服务层异常 → API 响应的映射在 T09 验证）。
