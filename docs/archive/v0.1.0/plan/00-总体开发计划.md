## 1. 文档体系与关联规范

### 1.1 三层结构

```
docs/devel/
├── design/                     # 设计定稿（事实源，不随实现改动）
│   ├── 01-前端设计方案.md       # v2.1
│   └── 02-后端设计方案.md       # v3 —— 本计划的任务来源
├── plan/                       # 开发计划（本层：流程 / 里程碑 / 追踪）
│   ├── 00-总体开发计划.md       # 本文档：规范 / 依赖链 / 追踪矩阵 / 进度汇总
│   └── M1~M8 里程碑文档         # 每阶段一份：目标 / 退出条件 / 风险
└── task/                       # 任务细化（执行单元）
    └── T01~T14 任务文档         # 每模块一份：任务条目 / 验收标准 / DoD
```

### 1.2 标识符规则

| 对象 | 格式 | 示例 | 说明 |
|---|---|---|---|
| 里程碑 | `M<序号>` | M2 | 与 `plan/M2-*.md` 文件名一致 |
| 任务 | `T<序号>` | T03 | 与 `task/T03-*.md` 文件名一致 |
| 任务条目 | `T<序号>-<n>` | T03-5 | 任务文档内的最小执行/引用单元 |
| 设计引用 | `02 §<节>` | 02 §6.1 | 指向 02-后端设计方案.md 对应章节 |

### 1.3 文档头信息块

每份 plan / task 文档头部使用引用块声明关联，固定字段：
**ID ｜ 所属（里程碑或任务清单）｜ 设计依据 ｜ 依赖 ｜ 状态 ｜ 最后更新**。
状态取值：`未开始 → 进行中 → 已完成`。

### 1.4 引用纪律（双向关联的建立方式）

- **plan → task**：里程碑文档的「任务清单」表列出所辖任务 ID 与相对链接；
- **task → plan / design**：任务文档头部声明所属里程碑与设计依据章节，正文以 `02 §x.y` 精确到节；
- **task ↔ task**：「依赖」与「下游」在任务文档头部双向声明；
- **design → plan/task 的反向索引**：由本文档 §5 追踪矩阵承担（设计文档保持定稿不动，不在其内部加链接）。

### 1.5 状态与变更管理

- 任务状态变化时，**同步更新本文档 §4 进度汇总表**（两处一致）；
- 任务范围变更时：修改对应 task 文档并在其变更记录留痕，若影响设计映射则同步 §5 矩阵；
- 里程碑状态 = 所辖任务全部已完成，且该里程碑文档的退出条件全部达成。

## 2. 开发流程总述

组织方式：**自底向上按依赖链**。理由：撮合 / 计划 / 策略内核为纯函数（02 §2.3 可移植、§4.1 无 I/O），最早完成即可用单测锁定风险最高的 A 股规则（02 §6.12 数值断言），后续服务层与 API 层在其之上装配；有状态服务（交易员/行情）与内核无依赖，可在内核完成后并行推进。

```
M1 工程骨架（T01 骨架与配置 · T02 持久层）
    ↓
M2 领域内核（T03 撮合引擎 · T04 计划引擎与策略）    ← 纯函数 + 全量单测，风险前置
    ↓
M3 基础服务（T05 交易员服务 · T06 行情服务）          ← 两者可并行
    ↓
M4 交易链路与会话（T07 交易服务 · T08 会话与日切）    ← 端到端交易闭环（尚无 API）
    ↓
M5 API 全能力层（T09 REST 与横切 · T10 WebSocket）    ← 完成后前端 v2 改造可并行启动
    ↓
M6 计划服务接入（T11）
    ↓
M7 统计与导出（T12 统计 · T13 导出）
    ↓
M8 验收与性能（T14）                                  ← 02 §6.12 全表终验收
```

里程碑内部任务尽量并行（T05 ∥ T06、T09 ∥ T10 开发可交叉）；跨里程碑按依赖顺序推进。

## 6. 验收策略

1. **条目级**：每个任务条目自带验收标准，任务完成 = 条目全过 + 该任务 DoD 达成；
2. **里程碑级**：退出条件见各里程碑文档（M1–M8）；
3. **终验收（T14）**：执行 02 §6.12 全表——引擎数值断言、鉴权矩阵、幂等重放、限速、审计、UI↔API 对照清单、生命周期全流转、性能基准（tick→广播 <200ms、单 tick 评估 <50ms、导出 1 万行 <2s、P95 <50ms）。
