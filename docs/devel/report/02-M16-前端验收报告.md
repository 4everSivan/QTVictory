## 6. 环境受限项（诚实登记）

**撮合成交全链路（买入 → 部分成交 → 撤单 → T+1 卖出）未在本机完成真实成交演练**：本机代理阻断 https 行情源（`qt.gtimg.cn` TLS 握手超时，http 可达但后端适配器按设计固化 https），后端处于 anchor 降级态、无股票档快照，下单被后端以 `SUSPENDED` 拒止（该回执链路本身已实测：UI → API → 错误包络 → field 文案映射）。
前端侧全部呈现路径（下单面板/回执刷新/partial 胶囊/ORD 分组/撤单/成交 Toast）已经组件级 127 用例 + 无头浏览器验证；**待有行情环境后按 T22-2 步骤单复验成交段即可**，不阻塞前端收口。

**2026-09-17 补充实测（todo EN-0001 推进记录，成交段仍未闭环）**：
- 拒单链路追加证据：8788 测试实例收盘态（`GET /api/session` → `{"state":"closed","tradingDate":"2026-09-17"}`）下，代交易员（id=2，manual，initCash 100 万）对 `sh000300`/`sh600519` 下限价/市价单均被拒，回执 `{"code":"SESSION_CLOSED","message":"当前非交易时段"}`——下单校验链首闸（会话状态）行为与设计 02 §3.6 校验顺序一致；
- 降级链现状复核：`GET /api/market/quotes` 仍 `source:"anchor", live:false`，sh000300 锚定价 4460.77、`bids/asks` 空；`qt.gtimg.cn` 直连与代理均不可达（curl 000）。无盘口深度则撮合无对手盘，成交段依旧无法演练；
- 服务层/引擎层回归证据（backend `.venv`，2026-09-17 复跑）：`pytest tests/service/test_trading.py tests/service/test_session.py` 21 例全绿（含 `test_t1_locked` T+1 锁定）；`pytest tests/unit` 53 例全绿（撮合引擎 `test_engine_match`/`test_engine_auction`/`test_engine_price` 覆盖部分成交与价格优先逻辑）；
- **结论**：撮合内核纯函数层与下单校验链已有回归与实测覆盖；环境依赖的"真实行情 → 真实成交 → 撤单 → T+1 口径"端到端演练仍待有行情环境后按 T22-2 步骤补测，EN-0001 保留在 todo 未移出。

**2026-09-18 09:47 第二次尝试（交易时段内，仍未闭环）**：
- 会话状态正常：`GET /api/session` → `{"state":"degraded","phase":"continuous","tradingDate":"2026-09-18"}`，连续竞价时段、降级态透出正确；
- 行情源复核（curl 实测）：腾讯 https 仍断（000）/ http 通（200）；**新浪 https + Referer 通（200）**；东财 https 仍断（000）。后端降级链（腾讯 https → 东财 → anchor）无新浪成员，故 `GET /api/market/quotes` 仍 `source:"anchor", live:false`、盘口空，成交段无法演练；
- **结论**：阻塞根因已明确为"降级链不含本机可达源"，解法登记于 todo EN-0006（新浪适配入链等）。EN-0001 继续保留在 todo，待 EN-0006 落地或网络环境恢复后复验。
