## 1. 目标与范围

交付观察员控制台的交易执行与回报全链路 UI：下单面板（§4.7 v2 全规则）、底部 Dock 三表（§4.8）、确认弹窗与 Toast（§4.10）。前端职责严守 §6 两层：**输入层即时校验仅为体验优化，最终以后端校验结果为准**；撮合/账户引擎不进前端（v1 `TRADE.*` 废止）。

## 2. 任务明细

### T20-1 下单面板结构
- **内容**：§4.7 纵向方案 A：右栏 56/44 分割（盘口+逐笔 ≤56%、下单面板 ≈289px @940）；body 内滚动（买卖方向钮与提交钮 `flex-shrink:0` 钉底，中间表单区滚动）；买卖分段 / 限价市价分段 / 价格步进 / 数量输入 / 快捷仓位 / 费用块 / 校验文案行；**市价类型 seg 仅市价态出现**（`最优五档剩余撤销`默认 / `对手方最优`，占一行），限价态隐藏；提交钮短文案"买入/卖出 代码"；无选中交易员时禁用并提示。
- **交付物**：`components/panes/OrderPanel.tsx`。
- **验收标准**：版式与分割比符合 §4.7 v2.1（几何截图核对）；表单超长时仅 body 滚动、方向钮/提交钮钉底；市价/限价切换 seg 显隐正确；未选中态禁用呈现。

### T20-2 输入层即时校验
- **内容**：§6.1 三层校验——**数量**：主板/创业板 100 股整数倍、科创板 ≥200 股 1 股递增（输入框即时校验文案随板块切换）；**价格双重区间**：涨跌停带 + 连续竞价 ±2% 有效申报范围，越界文案给出两区间；**可用口径预估**：可用资金 = 现金 − 买入冻结、可卖 = 持仓 − T+1 锁定 − 卖出冻结（冻结部分金色标注，§4.7）；费用预估块（佣金/印花税/过户费，注明"按五档加权近似，实际按成交回报"——市价单口径，§4.7）。
- **交付物**：校验纯函数模块（`validate/order.ts` 或等价）。
- **验收标准**：校验规则单测全覆盖（含科创板边界 200/199、±2% 与涨跌停交集区间文案）；冻结口径与后端字段一致；所有校验仅前端预估，提交仍以后端回执为准（§6 纪律注释明示）。

### T20-3 下单提交与回执
- **内容**：`POST /traders/{id}/orders`；确认弹窗标注"**以 XX（交易员名）身份下单**"+ 限价单提示"可能分批部分成交"（§4.7）；回执经 `trader:{id}` topic；失败回执经 [T16-5](T16-数据层与API客户端.md) 错误映射转为就地校验文案或 Toast（`LOT_SIZE / PRICE_BAND（两区间）/ INSUFFICIENT_FUNDS / T1_LOCKED / SESSION_CLOSED / STALE_QUOTE / RATE_LIMITED` 等）；提交防重（提交中禁用）。
- **交付物**：下单编排逻辑 + 确认弹窗。
- **验收标准**：成功下单后面板/Dock 即时反映；每类错误码有对应 UI 呈现用例；重复点击不产生重复委托（防重生效，后端幂等不替代前端防重）。

### T20-4 底部 Dock：持仓 / 当日委托 / 成交记录
- **内容**：§4.8：四 Tab 保留（收益分析 Tab 归 [T21](T21-计划收益与导出.md)，本任务做 Tab 骨架与三表）；数据全部按当前交易员过滤（跟随语义）；**委托表**：新增"已成交/委托量"列 + `partial` 状态胶囊（部分成交），撤单按钮保留且**集合竞价 9:20–9:25 禁用态**；**成交表**：按笔展示、按 `order_id` 分组——组头 10px 微标签（`ORD #7A1F · 限价买入 1285.50 ×100 · PARTIAL 60/100`）、组间 1px `#2a2a2a` 深线（结构区分分组，"分组着色"原文废止）；订单状态 `wait → partial → filled | cancel` 呈现；Tab 栏右侧"跟随 当前交易员"过滤指示器。
- **交付物**：`components/panes/Dock.tsx`（三表 + Tab 骨架）。
- **验收标准**：三表字段与后端端点逐项一致；撤单 `DELETE` 接 API 并刷新；9:20–9:25 禁用断言（会话状态驱动）；分组样式按 v2.1 微标签方案。

### T20-5 Toast 反馈体系
- **内容**：§4.10：Toast 三类——成交回报 / 撤单结果 / 风控事件（来源 `events` 与 `trader:{id}` topic）；成功/失败语义；动效遵守 §3.2（150–250ms 仅透明度）。
- **交付物**：Toast 组件 + 全局挂载。
- **验收标准**：三类事件各有用例；并发 Toast 不重叠溢出；自动Dismiss 时长一致。
