## 1. 目标与范围

SQLite 全量 Schema、迁移机制与 store 访问层：落实 02 §6.2 的十三张表，确立 WAL 单写者纪律与游标分页 helper。**注意**：本任务只建结构与访问能力，不实现业务语义（业务归 T05–T13）。

## 2. 任务明细

### T02-1 迁移机制
- **内容**：`migrations/` 版本化 SQL 脚本；启动时（lifespan 首阶段，T01-6）自动执行；迁移版本记录表；幂等可重跑。选型（轻量自研 vs alembic）在本条目内定夺并登记变更记录。
- **交付物**：迁移框架 + 首版全量建表脚本。
- **验收标准**：空库启动建出全部表；重复启动不重复执行；版本号单调推进。

### T02-2 全量建表（§6.2）
- **内容**：显式定义六表：`sync_state`、`audit_log`、`traders`、`orders`（含 `idx_orders_trader_date` 索引）、`corporate_actions`、`minute_klines`；并按 §6.2 注释约束补齐七表：`positions`、`trades`（**`order_id` 非唯一**：一单多笔）、`equity_snapshots`、`plans`、`plan_entries`、`trader_events`、`klines`；软删以 `traders.status='deleted'` 表达。
- **交付物**：schema SQL + 表结构文档注释。
- **验收标准**：与 §6.2 逐字段对照一致；注释中的结构约束（非唯一索引、软删约定）落实；字段疑点登记变更记录而非静默取舍。

### T02-3 WAL 与连接策略
- **内容**：启用 WAL（§2.3 可靠性）；写操作全部经 T01-5 串行基座（单写者）；读连接策略与异步访问方式（aiosqlite / 线程池）在此定夺并记录。
- **交付物**：连接管理模块。
- **验收标准**：`PRAGMA journal_mode=WAL` 确认；并发读写冒烟测试；写串行纪律单测。

### T02-4 store 访问层
- **内容**：各表基础 CRUD 与常用查询（按交易员/日期/状态过滤）；**游标分页 helper**（`?cursor=&limit=`，响应含 `nextCursor`，§5.1），供 T09 全部列表端点复用。
- **交付物**：`store/` 访问层 + 单测。
- **验收标准**：CRUD 单测全绿；分页边界（空结果、尾页、cursor 失效）用例通过。

### T02-5 数据约定
- **内容**：时间字段 ISO-8601 文本约定；金额 REAL 与两位小数边界；JSON 字段（`strategy_params` 等）序列化约定；`trading_date` 口径与 T08 推定值一致。
- **交付物**：约定文档（模块 docstring）+ 序列化测试。
- **验收标准**：JSON 字段往返序列化无损；时间格式全局一致。
