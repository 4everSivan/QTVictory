## 1. 目标与范围

计划体系接入运行时（02 §3.7）：计划与条件单 CRUD、PlanEngine 每 tick 调度、触发执行链、策略调度、gtc 续期。内核逻辑在 [T04](T04-计划引擎与策略模板.md)，本任务负责状态持有、调度接线与执行链。

## 2. 任务明细

### T11-1 计划与条件单 CRUD
- **内容**：计划（scope / budget / position_rule / risk / schedule）与条件单（四类触发器 × day|gtc × 动作）的增删改查（服务侧，端点在 [T09-2](T09-REST与鉴权幂等.md)）；计划删除级联撤单（调 [T07-3](T07-交易服务.md)）。
- **交付物**：PlanService CRUD。
- **验收标准**：CRUD 全操作用例；级联撤单后相关订单终态为 cancel。

### T11-2 PlanEngine 调度接线
- **内容**：每 tick 在串行基座内调用 PlanEngine（顺序对齐 §4.4：PlanEngine.tick → MatchingEngine.tick）；把内核输出的"状态变更指令"落库并回灌（触发防重复状态、续期状态）。
- **交付物**：调度接线层。
- **验收标准**：真实 tick 序列下条件单恰好触发一次；状态回灌后重启不重复触发。

### T11-3 触发执行链
- **内容**：条件单触发 → 生成订单（`origin=plan`）经 [T07-1](T07-交易服务.md) 校验链（含计划约束与 `PLAN_PAUSED`）→ 成交 → WS `plans` topic 事件（`entry_triggered` 等，经 [T10-2](T10-WebSocket与实时推送.md)）+ `trader_events` 留痕。
- **交付物**：执行链编排。
- **验收标准**：触发 → 下单 → 成交 → 事件推送全链路集成测试；拒单时条件单状态与事件正确。

### T11-4 策略调度
- **内容**：按 `traders.status`（running 才产出）与计划 `schedule.frequency` 驱动 Strategies（[T04-5](T04-计划引擎与策略模板.md)）→ 意图经围栏四道闸 → 下单（`origin=strategy`）。
- **交付物**：策略调度器。
- **验收标准**：`paused/closed` 交易员不产出任何意图；围栏拦截的意图有事件留痕不下单。

### T11-5 下单校验链计划约束接入
- **内容**：在 [T07-1](T07-交易服务.md) 校验链的"计划约束"检查点接入：策略围栏四道闸的运行时校验（scope→budget→position_rule→单笔），产出 `PLAN_CONSTRAINT`。
- **交付物**：校验点接入。
- **验收标准**：manual 下单对计划参数的约束行为用例；与 T07 测试集的联调用例（双方变更记录交叉登记）。

### T11-6 gtc 续期与到期
- **内容**：日切时 `tif=day` 条件单日终撤销、`gtc` 续期（由 [T08-2](T08-会话服务与日切.md) 日切序列调用）；计划到期检查。
- **交付物**：续期/到期逻辑。
- **验收标准**：跨日用例——day 撤销、gtc 存活、到期计划转终态。
