## 1. 文档体系与关联规范

### 1.1 三层结构

```

│   ├── 01-前端设计方案.md          # v2.1 —— 本计划的任务来源

├── plan/                          # 开发计划（本层：流程 / 里程碑 / 追踪）
│   ├── 00-总体开发计划.md          # 后端线总览（已完成收口，不再改动）
│   ├── 00-前端开发计划.md          # 本文档：规范 / 依赖链 / 追踪矩阵 / 进度汇总
│   ├── M1~M8 里程碑文档            # 后端线（全部已完成）
│   └── M9~M16 里程碑文档           # 前端线：每阶段一份：目标 / 退出条件 / 风险

    ├── T01~T14 任务文档            # 后端线（全部已完成）
```

### 1.2 标识符规则

编号在全局空间内延续后端线，不与 M1–M8 / T01–T14 冲突；格式规则与 [00-总体开发计划](00-总体开发计划.md) §1.2 完全一致：

| 对象 | 格式 | 示例 | 说明 |
|---|---|---|---|
| 里程碑 | `M<序号>` | M10 | 与 `plan/M10-*.md` 文件名一致 |
| 任务 | `T<序号>` | T16 | 与 `task/T16-*.md` 文件名一致 |
| 任务条目 | `T<序号>-<n>` | T16-3 | 任务文档内的最小执行/引用单元 |
| 设计引用 | `01 §<节>` | 01 §7.3 | 指向 01-前端设计方案.md 对应章节 |
| 后端接口引用 | `T09/T10-<n>` | T10-2 | 指向后端已完成任务条目（接口行为事实源） |

### 1.3 文档头信息块

每份 plan / task 文档头部使用引用块声明关联，固定字段：
**ID ｜ 所属（里程碑或任务清单）｜ 设计依据 ｜ 依赖 ｜ 状态 ｜ 最后更新**。
状态取值：`未开始 → 进行中 → 已完成`。

### 1.4 引用纪律（双向关联的建立方式）

- **plan → task**：里程碑文档的「任务清单」表列出所辖任务 ID 与相对链接；
- **task → plan / design**：任务文档头部声明所属里程碑与设计依据章节，正文以 `01 §x.y` 精确到节；后端接口行为以 `02 §5` + 后端任务条目为事实源；
- **task ↔ task**：「依赖」与「下游」在任务文档头部双向声明；
- **design → plan/task 的反向索引**：由本文档 §5 追踪矩阵承担（设计文档保持定稿不动，不在其内部加链接）；
- **前端线 ↔ 后端线**：本文档 §2 依赖链与 §5 矩阵引用后端 M/T 编号；后端线文档为已定稿历史，不再回改。

### 1.5 状态与变更管理

- 任务状态变化时，**同步更新本文档 §4 进度汇总表**（两处一致）；
- 任务范围变更时：修改对应 task 文档并在其变更记录留痕，若影响设计映射则同步 §5 矩阵；
- 里程碑状态 = 所辖任务全部已完成，且该里程碑文档的退出条件全部达成。

## 2. 开发流程总述

组织方式：**先地基后展示，展示层并行，交易链路收口**。理由：`api/` 数据层（01 §7）是所有面板的公共地基且对接面最危险（WS 断线、降级轮询、错误码映射），最先锁定；此后行情面板 / 图表组件 / 交易员模块三块展示层仅依赖数据层，可并行；交易链路依赖行情（价格校验）与交易员（作用对象），随后收口；计划/收益/导出依赖交易员上下文与图表组件，最后联调验收。后端 M1–M8 已全部完成（[验收报告](../report/01-M8-验收报告.md)），前端全程对接真实 API，无 Mock 阶段。

```
M9  工程骨架与样式基线（T15）                        ← 目录/令牌/双主题/栅格外壳
    ↓
M10 数据层与 API 客户端（T16）                       ← REST + WS + 错误映射 + 降级
    ↓
M11 行情面板（T17）∥ M12 图表组件（T18）∥ M13 交易员模块（T19）   ← 三展示层并行
    ↓
M14 交易链路（T20）                                  ← 下单/委托/成交/持仓/T+1 呈现
    ↓
M15 计划·收益·导出（T21）
    ↓
M16 联调验收与收口（T22）                            ← 01 §7.2 对照 + 双主题 + 几何/性能
```

里程碑内部任务按条目顺序推进；M11/M12/M13 三者无相互依赖，人员单排时按 T17 → T18 → T19 顺序执行。

## 6. 验收策略

1. **条目级**：每个任务条目自带验收标准，任务完成 = 条目全过 + 该任务 DoD 达成；
2. **里程碑级**：退出条件见各里程碑文档（M9–M16）；
3. **终验收（T22）**：按 01 §11 v1 验证方法补测——浏览器实测 + 几何校验（§2.2 栅格、§4.1 v2.1 字号纪律）+ 交易链路对后端真实回执；并执行 01 §7.2 UI↔端点映射表逐项对照（防能力漂移，对应后端 02 §6.12 精神）；双主题零报错；连接降级（§7.3）全路径演练。
