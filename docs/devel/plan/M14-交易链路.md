## 1. 目标

交付交易执行与回报全链路 UI：下单面板（§4.7 v2 全规则：市价类型 seg / 板块申报单位 / 双重价格区间 / 冻结口径 / 费用块 / 身份确认弹窗）、底部 Dock 三表（§4.8：partial 列与胶囊 / ORD 微标签分组 / 撤单禁用 / 跟随指示器）、Toast 体系（§4.10）。前端职责严守 §6 两层（输入校验为体验层，后端回执为准）。

## 2. 退出条件

- [x] 下单面板按 §4.7 纵向方案 A 落地：56/44 分割、body 内滚动钉底、市价类型 seg 仅市价态、提交钮短文案、未选中禁用；
- [x] 输入层校验全绿：整百/科创板 ≥200 1 股递增（文案随板块切换）、涨跌停带 + ±2% 双区间越界文案、可用/可卖冻结口径金色标注；
- [x] 下单回执链路：确认弹窗身份标注 + `trader:{id}` 推送刷新 + §6 错误码逐项呈现（含 `PRICE_BAND` 双区间，SUSPENDED 实测）；
- [x] Dock 三表按 §4.8 v2.1：委托 partial 列/胶囊、成交按 `order_id` 分组微标签（组间 1px `#2a2a2a`）、撤单 9:20–9:25 禁用、跟随指示器；
- [x] 端到端链路对后端真实回执部分通过（下单→校验回执）；撮合成交全链路因行情源环境受限登记 T22 复验；
- [x] Toast 三类事件（成交/撤单/风控）呈现正确（成交/部分成交经委托快照差分派生），动效符合 §3.2。
