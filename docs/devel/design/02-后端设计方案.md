## 1. 简介

本方案定义 QTVictory（A 股实时交易模拟器）的后端系统：行情采集、观察员与交易员体系、模拟撮合、交易计划、绩效统计、数据导出与持久化，以及全能力 API（REST + WebSocket）。

系统定位：**面向量化交易系统的模拟底座**（系统宏观架构全景与多阶段演进蓝图详见 [00-宏观架构与演进设计方案.md](00-宏观架构与演进设计方案.md)）——以真实行情与真实交易规则（费用/T+1/涨跌停/整手）构建高仿真实时环境，供策略程序在前向测试（paper trading）中验证、对比与评估；观察员管理的每个交易员即一个被测策略实例（或手动基线），绩效统计与数据导出服务于策略分析。

## 2. 需求

### 2.1 范围

- **范围内**：单机自部署、真实行情轮询接入、模拟撮合全规则、观察员-交易员体系、交易计划引擎、数据导出、每日净值落库。**产品形态为实时前向仿真（跟随真实行情的模拟交易）**。
- **范围外（本版不做）**：实盘通道、Level-1 行情订阅、分布式部署、多观察员/细粒度权限体系；**历史回测引擎**（加速重放/K线回测属后续独立系统，本系统为其提供规则内核与评估口径的统一底座）。

### 2.2 功能需求

| # | 需求 | 说明 |
|---|---|---|
| F1 | 实时行情 | 轮询腾讯免费接口（快照/日K/分时/指数），统一规范化输出；上游故障自动降级（备用源 → 内置锚点）并透出 `source/live` 状态 |
| F2 | 观察员 | 系统仅初始化一个观察员；观察员可操作交易员的**任何信息**：全生命周期管理、代下单/撤单、计划管理、注资/重置；全部操作经 API 完成 |
| F3 | 交易员 | 任意数量创建；名称、模式（手动/策略模板+参数）、任意初始资金；暂停/恢复/关闭归档/删除；账户（现金/持仓/委托/成交/净值）为从属视图 |
| F4 | 模拟撮合（**与 A 股市场规则统一**） | 盘口五档驱动 + 成交量约束 + **部分成交**；市价单类型（最优五档剩余撤销/对手方最优）；限价单排队语义（穿越触发、量约束分批、成交价=委托价）；**资金/持仓冻结**；连续竞价有效申报范围（±2%）；集合竞价（开盘/收盘按集合竞价价撮合）；申报单位按板块（主板/创业板 100 股整数倍、科创板 ≥200 股 1 股递增）；**品种准入白名单：仅沪深主板/创业板/科创板个股可交易（〔C015〕，见 §6.1 规则适用范围）**；停牌拒单；佣金/印花税/过户费；T+1；涨跌停；日内有效；订单来源 manual / operator / plan / strategy |

| F6 | 绩效统计 | 每交易日收盘对全体交易员落净值快照；总收益率/年化/最大回撤/夏普/胜率/超额 vs 沪深300；排行榜 |
| F7 | 数据导出 | 按交易员导出交易信息：成交/委托/持仓/净值/计划，CSV 与 JSON 两种格式，支持时间区间过滤，同步流式下载 |
| F8 | API 完备性 | **UI 能做的 API 都能做**：全部交易员操作可程序化调用；OpenAPI 全覆盖；写操作幂等；操作审计 |
| F9 | 实时推送 | WebSocket 推送行情、账户变动、交易员动态与生命周期、计划触发事件；REST 兜底 |

### 2.3 非功能需求

- **延迟**：tick → 撮合/计划评估 → WS 广播 < 200ms（本机）；接口 P95 < 50ms。
- **上游纪律**：快照批量（全体交易员标的池并集）；连续竞价 3s、休市 60s；指数退避与熔断。
- **API 机器友好**：写操作支持 `Idempotency-Key`；列表游标分页；统一错误模型；令牌桶限速（默认 20 req/s，超限 `429` + `Retry-After`）。
- **可靠性**：SQLite WAL 单写者；行情失败不阻断交易（新鲜度标注）。
- **一致性**：订单/计划触发/观察员操作在同一事件循环串行化。
- **审计**：观察员的全部变更类操作落审计日志，只增不改。
- **可移植**：撮合/计划/策略纯函数可单测。

## 3. 功能设计

### 3.1 领域模型

```
Observer（观察员，系统唯一，首次启动初始化）
  ├─ 权限：交易员全生命周期管理（创建/修改/暂停/删除/注资/重置）
  │        代任意交易员下单/撤单、计划与条件单管理、数据导出、审计查询
  └─ 边界：不直接交易、无账户、不参与排行榜（Q1 决议）
             手动交易 = 创建 manual 模式交易员，由观察员代为下单

Trader（交易员，任意数量，初始世界为空）
  ├─ 账户：初始资金任意设定、现金、持仓、委托、成交、净值
  ├─ 模式：manual（由观察员代操作）｜ strategy（策略自动，8 种预置模板 + 参数）
  └─ 交易计划：标的池 / 预算 / 仓位目标 / 止损止盈 / 条件单
```

**订单来源（origin）语义**：`manual` = 观察员经 Web UI 代交易员下单；`operator` = 外部程序经 API 代下单——二者同为观察员动作，仅区分入口便于分析；`plan` = 条件单触发；`strategy` = 策略输出。

**量化底座语义**：Trader ≈ 被测策略实例（strategy 模式）或手动基线（manual 模式）；多交易员并行 = 多策略 A/B 对比；净值序列与绩效指标 = 策略评估口径；数据导出 = 策略分析的原始数据出口。外部量化程序以 API-first 方式接入：WS 消费行情 → 决策 → REST 下单/管理。

### 3.2 模块总览

| 模块 | 层 | 职责摘要 |
|---|---|---|
| MarketService 行情服务 | 服务 | 腾讯源轮询与规范化、三级降级链、日K/分时缓存、交易日历推定 |
| TraderService 交易员服务 | 服务 | 交易员 CRUD 与状态流转、策略模板实例化、注资/重置、账户从属视图 |
| TradingService 交易服务 | 服务 | 下单校验链（含计划约束）、订单生命周期、撮合执行 |
| PlanService 交易计划服务 | 服务 | 计划与条件单 CRUD、触发评估、风控钩子、策略围栏 |
| MetricsService 统计服务 | 服务 | 收盘结算快照、绩效指标计算、排行榜数据 |
| ExportService 导出服务 | 服务 | 五类数据 × CSV/JSON × 区间过滤的导出 |
| SessionService 会话服务 | 服务 | 交易时段状态机、日切流程编排 |
| MatchingEngine / PlanEngine / Strategies | 领域 | 纯函数内核：撮合规则 / 计划触发与风控 / 8 策略模板 |

### 3.3 观察员（系统初始化与权限）

- **初始化**：首次启动创建唯一观察员（`sync_state.observer_initialized`）；`QTV_API_KEY` 为可选凭证（**Q4 决议：纯私人本机使用，默认免鉴权、仅监听 127.0.0.1 并日志告警；启用后所有 REST/WS 调用必须携带**）。
- **权限面**（全部经 API）：交易员 CRUD 与状态流转；代任意交易员下单/撤单；计划与条件单 CRUD；注资/重置；自选股管理（〔v6 新增〕，§3.10）；数据导出；审计查询。
- **边界**：无账户、不交易、不参与排行榜；无第二个观察员，无细粒度权限（单机自用假设）。
- **审计**：观察员全部变更类操作（POST/PATCH/DELETE）写 `audit_log`（who=observer, what, target, payload 摘要, ts），只增不改；`GET /api/audit` 分页查询。

### 3.4 行情服务（MarketService）
交易时段 3s 批量快照（GBK 解码、字段位映射、科创板 688 成交量 ÷100 归一）；**快照完整保留五档买卖盘口（字段 9–28）与当日累计成交量**（相邻 tick 差分 = 周期增量成交量，作为撮合量约束基数）；停牌标志（快照价量静止/停牌位）透出给撮合拒单；日 K **启动拉取全量历史**（数千根一次性入库，量级 MB 级；腾讯 ifzq 失败自动落东财 push2his 兜底，量纲一致）+ **日切步骤 5 关注集日K重拉**（〔C014〕原"每日增量"为 noop 缺陷已修复：观测到新交易日执行日切时异步逐码重拉关注集日K，`upsert_klines` 幂等覆盖、上游为最终权威，单码失败仅告警不阻断日切序列；同时承担除权后前复权重锚自愈）；**分钟线自部署日起逐日累积**（〔C012 修订〕新分钟桶触发增量落库 + 停机终态刷盘 + 日切收口三层保障，`minute_klines` 幂等 upsert，当日盘中即可经 `/market/minute` 读取，崩溃/重启损失收敛到当前未完成分钟；历史分钟回补不做——免费源分钟历史深度有限且质量差，标注为已知边界；〔C010〕快照时间戳字段 30 实测为 `YYYYMMDDHHMMSS`，适配器统一归一为 `HH:MM:SS`，不可解析时间戳（如降级源空 ts）不落分钟桶，杜绝单桶失真；〔C018〕**时段门禁**——仅 09:30–11:30 / 13:00–15:00（与前端 242 槽精确对齐）落桶，盘后/周末快照 ts 落槽外垃圾桶的缺陷修复；**`/market/minute` 缺省 date 回退**——未显式传 `date` 且 trading_date 当日无行时，回退该码最近有分时数据的交易日（响应 `date` 如实标识），非交易时段可展示最近交易日分时；显式 `date` 精确查询不回退；〔C019〕**最近交易日分时引导**——缺省查询回退仍空时，在线触发腾讯 `app/day/query` 拉取最近交易日单日全量分时（与实时落桶同时段门禁、同量纲累计量，失败/空结果 10 分钟冷却），幂等 upsert 后返回；**仅补最近一个交易日，更深历史不回补（Q8 边界修订，2026-09-20 会话拍板）**）；**每日收盘任务拉取次日除权除息与分红送配方案**（入 `corporate_actions` 表，供日切处理）；分时当日缓存；降级链 **腾讯（https→http 协议兜底）→ 新浪（https + Referer 头）→ 东财 → 内置锚点**并透出 `source/live`（**新浪档含五档与当日累计量，视同主源完整档参与 ΔV 差分与盘口撮合；东财/锚点降级档无盘口与增量量，撮合自动回落固定滑点全量成交档并在订单上标注 `fill_model=fallback`**）；交易日历由快照时间戳推定（〔C017〕**未来日期守卫**：日切仅在库存日期 < 真实当日时触发；库存日期为未来日期时绝不切账——≤7 天的小步超前视为日切推进到的次交易日（跨周末/法定连休）保持不动，>7 天或不可解析判为时钟回拨/状态污染，告警并重同步为真实当日）。关注代码集动态：**自选集（§3.10，〔v6 新增〕）** ∪ 全体交易员持仓 ∪ 全体计划标的池（〔C011〕裸码读取边界惰性归一为前缀规范码）∪ 指数（并集语义不变，自选集为 v6 新增第四支；自选删除后若仍被持仓/计划引用，继续留在关注集）。

### 3.5 交易员服务（TraderService）
- 生命周期：创建（名称/模式/策略参数/任意初始资金/可选初始计划/可引用策略模板）；`paused` 暂停策略与计划触发；`closed` 归档（退出排行榜，历史保留）；删除默认软删（硬删需显式 `?hard=true` 并二次审计）。
- **策略模板（Templates）**：8 种**示例策略**（趋势跟踪/均值回归/网格/动量突破/长线价值/短线快进/事件驱动/保守配置，参数与前端 v1 §8 一致）——定位是平台功能验证与绩效基线参照，非产品内容；`GET /api/templates` 列出，创建交易员可 `template: "momentum"` 快速实例化。
- 账户视图/重置/注资：重置保留净值快照断点；注资调增 init_cash 保持收益率口径。
- **初始世界为空**（Q2 决议）：首次部署仅观察员、零交易员，不做演示播种；空态由前端引导创建。

> 📌 **关联变更**: [C003 - 交易员编辑态 strategyParams 读取端点](../change/C003-交易员编辑态strategyParams读取端点.md)（`GET /traders/{id}` 详情响应增补 `strategyParams`，manual 为 null）

### 3.6 交易服务（TradingService）
下单校验链：会话状态 → 交易员状态 → 停牌 → **品种准入白名单（〔C015〕，仅沪深主板/创业板/科创板个股，详见 §6.1 规则适用范围）** → **申报单位（板块差异，见 §6.1）** → **有效申报价格范围（连续竞价 ±2% 与涨跌停带取 tighter 者）** → 市价单类型 → **资金/持仓冻结（买入冻结全额+费用余量、卖出冻结股份，撤单/日终解冻）** → 可用资金/可卖（T+1 且扣除冻结）→ 计划约束 → 生成订单（origin 见 §3.1）。订单生命周期与撮合模型见 §6.1。

> 📌 **关联变更**: [C015 - 品种准入白名单](../change/C015-品种准入白名单.md)（校验链插入品种准入环节，指数/基金/债券/北交所等行情可及但规则未覆盖品种拒单）

### 3.7 交易计划服务（PlanService）
计划（scope/budget/position_rule/risk/schedule）+ 条件单（price_cross / pct_change / time / ma_cross，day/gtc）+ PlanEngine 每 tick 触发评估、风控钩子（止损止盈/日亏损熔断）、策略围栏四道闸（池内→预算→仓位→单笔），详细规格见 §6.7。**标的池代码归一**（〔C011〕与 §3.10 自选归一同源）：创建时逐码归一落库（带前缀直取；裸 6 位按板块规则推导主市场前缀，如 601318→sh601318、000001→sz000001 个股语义；非法码 422 `BAD_CODE` 拒绝），读取边界（围栏/tick 调度/关注集/视图回显）惰性归一，存量裸码行自动愈合。**标的池品种准入**（〔C015〕）：归一后逐码过可交易白名单（§6.1 规则适用范围），指数/基金/债券/北交所等规则未覆盖品种 422 `UNSUPPORTED_BOARD` 拒收。

> 📌 **关联变更**: [C011 - 修复计划标的池裸码不归一静默落空](../change/C011-修复计划标的池裸码不归一静默落空.md)（scope.codes 创建归一 + 读取边界愈合，裸码计划不再静默落空）
> 📌 **关联变更**: [C015 - 品种准入白名单](../change/C015-品种准入白名单.md)（计划创建标的池归一后增品种准入校验，错规则品种显式拒收）

### 3.8 统计与导出服务（MetricsService / ExportService）

**统计**：收盘结算对全体未关闭交易员落 `equity_snapshots`；指标（总收益率/年化/最大回撤/夏普/胜率/超额）基于真实快照。

**导出**：

| 类型 | 内容 | 说明 |
|---|---|---|
| trades | 成交明细 | 时间/代码/名称/方向/价/量/费用/已实现盈亏/来源(origin) |
| orders | 委托明细 | 含状态/成交价/来源/条件单回链 |
| positions | 当前持仓 | 快照式（含可卖/浮盈） |
| equity | 净值序列 | 日期/总资产/现金 |
| plans | 计划与条件单 | 含状态与触发记录 |

格式 `csv`（UTF-8 BOM，Excel 兼容）与 `json`；`from/to` 时间区间过滤；同步流式输出（`Content-Disposition` 附件）。**Q5 决议：不做异步导出任务**——本机 SQLite 量级下流式秒级完成；升级触发条件：单次导出超 10 万行或响应超 5s 时再引入异步任务。

### 3.9 会话服务（SessionService）

### 3.10 自选股服务（WatchlistService）〔v6 新增〕

- **模型**：自选集为**观察员级全局唯一清单**（不属任何交易员），落 `watchlist` 表（§6.2）；品种不限——股票/指数/ETF 等行情源可及代码均可收录；自选集**仅影响行情关注集**，不参与撮合、下单校验与风控围栏。**可交易品种以 §6.1 规则适用范围白名单为准（〔C015〕）**——品种不限仅为行情层口径，指数/ETF/北交所等收录后可看行情，下单/入计划池将被拒。
- **代码归一**：落库码为**带市场前缀规范码**（如 `sh600519`）——qt.gtimg.cn 仅识别前缀码；裸 6 位码/大写变体按板块规则（沪深主板/科创/创业板/场内基金/北交所）推导候选前缀、逐个快照探测，以首个命中码落库；写法变体幂等归一（重复添加返回原态）。
- **关注集并集**：行情关注代码集 = 自选 ∪ 全体交易员持仓 ∪ 全体计划标的池 ∪ 指数（§3.4）；自选删除后若仍被持仓/计划引用，继续留在关注集（前端按动态项呈现，不可删）。
- **添加即拉取日K**：新增自选成功后**异步**触发该代码日K 引导（复用启动引导同款链：腾讯 ifzq → 东财 push2his 兜底，量纲一致），使图表即刻具备历史；分钟线维持 Q8 决议边界（自收录日起逐日累积，历史不回补）。
- **校验与幂等**：`PUT/DELETE /watchlist/{code}` 单码幂等（删除不存在视为成功）；校验失败统一 `BAD_CODE`（400，`details.reason ∈ {BAD_FORMAT, UNREACHABLE, SUSPENDED}`——停牌码拒加，复盘后方可收录），探测网络异常 `QUOTE_SOURCE_ERROR`（503）；`POST /watchlist/batch` 批量增删**逐码校验**（代码格式 + 行情源快照可达性）、**部分应用**（合法码应用、非法码跳过）、**逐码回执** `{code, op, ok, error}`（`op` 区分同批同码的增/删向）；批量添加的日K 引导串行排队，引导失败不阻塞添加回执。
- **名称联想**：`GET /market/suggest?q=` 代理腾讯 smartbox 联想接口（GBK 解码、名称字段 `\uXXXX` 转义还原、规范化 `{code, name, kind}`（GP-A/B→stock、ZS→index）、服务端 30s 短缓存、上游故障返回空列表），前端不直连外部行情源（API-first 原则不变）。
- **审计**：自选股全部变更类操作（PUT/DELETE/POST）写 `audit_log`（§3.3 口径）。

### 3.11 K线分析数据底座（多周期K线服务）

> 来源 FT-0009（2026-09-18 登记 future.md，2026-09-20 迁入 now.md 立项 [M18-K线分析工具](../../archive/v0.1.0/plan/M18-K线分析工具.md)）；前端消费方为 [01 §5 图表规格](01-前端设计方案.md)（衔接讨论稿后出）。2026-09-18 会话对抗评审通过（Q9–Q12 决议确认，纪要未入库、结论回写 §6.13）；实现验收后随下一正式版本转现行基线（对齐 §3.10/v6.0 流转先例）。

**职责边界**：后端只保障 OHLCV **数据完备性**——周期维度、历史深度、复权口径、新鲜度；展示型技术指标（MACD/RSI/BOLL/KDJ 等）为 OHLCV 的确定性无状态派生，计算归**前端纯函数层**（Q9）；交易域指标（PlanEngine `_ma` 收盘价窗口触发口径）内聚交易域，不与展示层复用；Phase 3 回测引擎（FT-0006）复用本节的聚合内核与视图形态——**qfq 序列含前视偏差（以当前价为锚回溯调整），仅限展示与研究；回测数据须另建 point-in-time 口径（不复权价 + 复权因子，或后复权），此为 FT-0006 立项硬约束（Q10）**。

- **多周期聚合**：统一冷热序列（`kline_view`）之上增加**纯函数聚合内核**——week 按 ISO 自然周（周一界）、month 按自然月切分；period 内首日 open、末日 close、max high、min low、sum volume；周/月K 的 `date` 取该 period 内最后交易日（主流行情软件口径）；**不落表、不缓存**（单码 ≤800 行 O(n) 聚合，本机单用户量级无缓存意义）；`limit` 语义 = 聚合后根数（week 按约 5N+缓冲换算取日K再截尾）。**已考虑并否决**：源端原生周/月K（ifzq `,week` / 东财 `klt=102/103`）——klines 单一事实源、聚合与库内数据精确一致、免改 adapter 与引导链（Q10）。
- **API 修正**：`GET /market/kline` 的 `period` 枚举定为 `day | week | month`；原 `period=minute` 为假参数（校验放行但实际返回日K行，既有接口缺陷）——**minute 假参数移除已随 [C013](../change/C013-修复kline接口period假参数.md) 落地（2026-09-18，非 day 值返回 `BAD_REQUEST`）**，分时统一走 `/market/minute`；**`week|month` 聚合放行已随 [T26-多周期聚合与K线API](../../archive/v0.1.0/task/T26-多周期聚合与K线API.md) 落地（2026-09-20，limit 语义 = 聚合后根数）**。
- **复权口径（明示锚定）**：日K全链路**前复权**——腾讯 ifzq `qfq` 与东财 push2his `fqt=1`（C008 已对齐量纲），后续新增行情源必须保持同口径并加测试锚定。已知边界：除权后前复权因子变化，重叠历史区间经校准重拉 `upsert_klines` 幂等覆盖即自愈，库内不保留多版本；**除权事件（F10 处理路径）后必触发一次校准重拉，重拉深度 ≥ 库存深度**（`QTV_KLINE_DEPTH` 同时约束两者，防旧自沉淀 bar 与重锚后序列错位）。
- **历史深度**：日K引导深度 320 → 800 根，经 `QTV_KLINE_DEPTH` 可配（默认 800，**上限 le=800**；单源拉取失败回落 320 不阻断引导链）。量级核对：800 交易日 ≈ 165 根周K / 38 根月K——周线 MA60（需约 300 交易日）、月线 MA20（需约 480 交易日）均可计算；`upsert_klines` 幂等，存量库加深无破坏。2026-09-18 本机实测：ifzq `,,,800,qfq` 返回 801 行（含当日盘中 bar）、`,,,1600` 仅 641 行——**qfq 深度封顶约 640~800，>800 不保证**，800 即近似上限；东财 push2his https 裸 curl 空回复（与 C008 网络怪癖同构），兜底档容量按 adapter 同款请求头复测后再定回落语义（Q11）。
- **冷热双态 bar 模型（Q12 决议，评审两轮修订定稿）**：
  - **热 bar** = MarketBus 快照——`open/high/low/last/cum_volume` 为上游维护的**当日累计态**（vendor 全 tick 流口径，非本地 3s 采样），盘中即当日 bar；实现落地时此语义同步写进 §3.4 领域模型（Quote 即当日 bar 聚合态），不做任何端点级"注入"；
  - **冷 bar** = `klines` 表仅存**完结 bar**（语义不变）；`price()`、PlanEngine `ma_cross`（收盘口径）、Phase 3 回测数据泵直读纯冷序列——**展示/API 读冷热合成序列，触发/回测读纯冷序列**（双读者路径，语义零变化）；
  - **换日捕获自沉淀**：`_ingest` 换日检测处、快照被新日数据覆盖**之前**，将完结热 bar 落库（与 C012 分钟线自沉淀同构对称）；落库门禁按源分级——tencent/sina（live 完整档）必落、eastmoney（真实价但字段可能不全）视 OHLC 有效性、**anchor 恒不落**（人造价格禁止入冷序列）；并入 day-cut 既有 `daycut:{d}:{step}` 断点机制，幂等可重入；
  - **校准重拉兜底**：跨换日停机错过捕获、历史缺口、除权后 qfq 重锚三种情形由上游重拉覆盖（upsert 幂等）；冲突时**上游为最终权威**，不构成双头权威；
  - **统一视图 `kline_view`**：冷 ∪ 热（交易日未完结时）为纯函数，降级档缺当日 OHLC 时热 bar 缺席、诚实少最后一根，不造假 bar；前端不再合成当日 bar，仅保留 kline 缓存刷新策略。
- **Schema**：零变更——`klines` 表（日粒度单一事实源）不动，周/月K为无状态派生视图。

## 4. 架构设计

### 4.1 设计原则

**API-first**：系统全部能力一律经 REST/WS 暴露，Web UI 只是 API 的一个客户端，不持有任何独占权限——交易员的任何操作（创建与配置、下单撤单、计划管理、资金操作、数据导出）均可程序化调用，写操作以幂等键保障重试安全，为后续任意外部驱动程序（脚本、策略框架、智能体等）接入预留完整且一致的机器接口。

其余原则：撮合/计划/策略内核纯函数化（无 I/O，可单测）；单一事件循环串行化全部状态变更；上游依赖可降级（行情三级降级链）。

### 4.2 技术选型
Python 3.11 + FastAPI + uvicorn；SQLite（WAL）；httpx；pydantic v2；asyncio 原生任务。

### 4.3 分层结构

## 5. 接口设计

### 5.1 通用约定

- **鉴权**：配置 `QTV_API_KEY` 后，全部端点要求 `X-API-Key`（读端点可配 `QTV_PUBLIC_READ=true` 放行只读）。
- **幂等**：全部写操作接受 `Idempotency-Key` 头（或订单的 `clientOrderId`）；重复提交返回首次结果。
- **分页**：列表端点游标式 `?cursor=&limit=`，响应含 `nextCursor`。
- **限速**：令牌桶 20 req/s（`QTV_RATE_LIMIT` 可配）；`429` + `Retry-After`。
- **错误模型**：`{"code", "message", "details"}`；码表见 §5.4。

### 5.2 REST（前缀 `/api`，观察员全能力）

| 方法 | 路径 | 说明 |
|---|---|---|

## 6. 详细设计

### 6.1 撮合引擎（MatchingEngine，A 股规则级仿真，Q3 决议 B）

**规则适用范围（品种准入白名单，〔C015〕）**：撮合与下单/计划校验仅覆盖**沪深主板（sh60/sz00）、创业板（sz30）、科创板（sh68）个股**——与涨跌停带、申报单位、费用规则的覆盖面精确一致；指数、基金/ETF、债券、北交所等品种行情可及（自选/关注集品种不限，§3.10）但**不可交易**，下单 400 / 计划创建 422 以 `UNSUPPORTED_BOARD` 拒单，杜绝错规则静默撮合。北交所 ±30%、主板 ST ±5%、ETF 免印花税/部分 T+0 等规则补齐为后续储备方向（[FT-0018](../todo/future.md)）。

> 📌 **关联变更**: [C015 - 品种准入白名单](../change/C015-品种准入白名单.md)（新增规则适用范围白名单：engine `tradable_ok` 纯函数 + 下单校验链/计划标的池两处拦截）

**数据基础（每 tick）**：五档买卖盘口（快照字段 9–28）、周期增量成交量 `ΔV`（累计量差分）、最新价/昨收。

**成交量约束**：单个交易员单个标的每 tick 成交量 ≤ `ΔV × QTV_VOLUME_PARTICIPATION`（默认 25%）；多交易员竞争同一标的时共享同一限额池（按到达顺序分配）——防止多个实例合计穿透真实流动性。

**市价单（type=market，marketType）**：
| marketType | 行为 |
|---|---|
| `best5_cancel`（默认） | 最优五档即时成交剩余撤销：按快照五档逐档吃单（每档受档位挂量与限额双重约束），成交均价按各档加权，**剩余未成交部分即时撤销** |
| `opponent_best` | 对手方最优价格：以对手方一档价格与量成交，剩余撤销 |
| 其余类型（本方最优/全额成交或撤销等） | 后续版本 |

固定 ±0.05% 滑点**移除**——滑点由盘口深度与量约束自然产生；行情降级模式下回落固定滑点全量成交档（订单标注 `fill_model=fallback`）。

**限价单（排队语义）**：
- 触发：最新价穿越委托价（买：last ≤ price；卖：last ≥ price）；
- 成交量 = min(等待量, 该标的当 tick 限额剩余)，**部分成交**累计（`filled_qty < qty` 继续 waiting，下 tick 继续）；
- 成交价 = 委托价（真实排队成交价即限价）。

**集合竞价（9:15–9:25 / 14:57–15:00）**：接受委托（9:20–9:25 不接受撤单）；9:25/15:00 集合竞价价产生后，限价单按穿越检查（买单价 ≥ 集合竞价价即成交）、市价单直接成交，成交价 = 集合竞价价，量约束按集合竞价时段成交量的比例简化。

**申报单位（板块差异）**：
| 板块 | 规则 |
|---|---|
| 主板（60/00） | 100 股整数倍 |
| 创业板（30） | 100 股整数倍 |
| 科创板（688） | 首次申报 ≥200 股，此后 **1 股递增**；卖出时余额 <200 股须一次性卖出 |

**有效申报价格范围（连续竞价，叠加于涨跌停带之内取 tighter）**：买入申报 ≤ 卖一价 ×102%（无卖一档时取最新价）；卖出申报 ≥ 买一价 ×98%。越界拒单（`PRICE_BAND`，details 返回两个区间）。

**资金/持仓冻结**：买入下单冻结 `price × qty × 1.002`（含费用余量），部分成交按比例扣减，撤单/日终解冻；卖出下单冻结股数。可用资金 = cash − 冻结额；可卖 = 持仓 − today_bought − 卖出冻结。

**费用/涨跌停/T+1/加权成本**：公式不变（v1 §6 表；〔[C020](../change/C020-修复calc_fee过户费率高估10倍.md)〕过户费 2022-04-29 起按成交金额十万分之一双向计收）；涨跌停带 = 主板 ±10%、创业板/科创板 ±20%（`round(昨收×(1±k), 2)`）；停牌标的拒单。

> 📌 **关联变更**: [C020 - 修复calc_fee过户费率高估10倍](../change/C020-修复calc_fee过户费率高估10倍.md)（过户费率 0.0001 → 0.00001：对齐中证登 2022-04-29 起现行口径，系统性费用高估 10 倍修复）

**订单状态机**：`wait → partial → filled | cancel`；一笔订单对应 0..n 笔成交（trades.order_id 非唯一）；cancel 来源 = 用户撤单（可撤窗口：连续竞价与 9:15–9:20）/ 收盘日终 / 计划删除级联。

### 6.3 观察员与鉴权
默认免鉴权（Q4 决议：项目纯私人使用、不部署公网）：仅监听 127.0.0.1，启动日志提示"无鉴权模式"；可选配置 `QTV_API_KEY` 后：REST 校验 `X-API-Key`（常量时间比较）、WS 握手经 `?key=`。审计中间件：所有非 GET 请求落 `audit_log`（失败请求同样记录，鉴权关闭时同样生效）。

### 6.4 会话时钟与日切流程
交易日期由快照时间戳推定；**日切触发条件（〔C017〕）**：仅在库存交易日期 **< 真实当日** 时触发（观测到新交易日）；库存日期为未来日期时绝不切账——≤7 天小步超前为日切推进到的次交易日（跨周末/法定连休）保持不动，>7 天或不可解析判为污染、告警重同步为真实当日（修复前周末起每轮 poll 伪日切滚雪球，trading_date 可被推进到远未来）。日切序列（幂等可重入）：日终撤单（全体交易员 + day 条件单）→ 收盘快照（全体未关闭）→ **公司行动处理（次日除权标的：按登记日持仓执行现金分红入账与送转股调整，见 §6.6）** → T+1 重置 → **日 K 增量（〔C014〕落实为关注集日K重拉：异步逐码拉取 + `upsert_klines` 幂等覆盖，单码失败不阻断；原为 noop 缺陷，修复前长运行实例 klines 末根冻结于启动时刻）** → **当日分钟线落库（`minute_klines` 累积，Q8 决议）** → 计划到期检查 → 交易日期推进。

> 📌 **关联变更**: [C014 - 修复日K每日增量noop改日切关注集重拉](../change/C014-修复日K每日增量noop改日切关注集重拉.md)（日切步骤 5 由 noop 落实为关注集日K重拉）
> 📌 **关联变更**: [C017 - 修复trading_date未来日期无守卫致日切滚雪球](../change/C017-修复tradingdate未来日期无守卫致日切滚雪球.md)（日切触发条件收紧为库存日期 < 真实当日，未来日期守卫三分支）

### 6.5 轮询器（QuotePoller）
3s/60s 动态间隔；关注代码 = 持仓 ∪ 计划池 ∪ 指数；超时 5s、连续 3 败熔断 60s 切东财备源、再败锚点降级；GBK/字段位/688 量纲 ÷100；新鲜度 >30s 拒市价单。

### 6.6 公司行动（Q7 决议 A）
- **现金分红**：除息日处理 `现金 += 登记日持仓 × 每股派息 × (1 − QTV_DIVIDEND_TAX)`；红利税按统一税率（默认 10%，`QTV_DIVIDEND_TAX=0` 即免税），**差异化持有期计税（>1年免/1月–1年10%/<1月20%，卖出时补扣）不做**，标注为已知简化。
- **送转股**：`股数 = 原股数 × (1 + 送股比 + 转增比)`（按公告比例精确到股，零股并入）；`avg_cost = 原成本总额 / 新股数`（成本摊薄）；到账股份**不占用 today_bought**（除权日即可卖出，符合真实规则）。
- **除权参考价**：除权日 `prev_close` 直接采用行情快照的除权参考价（数据源已处理），无需自行计算。
- **事件留痕**：分红/送转入 `trader_events`（action=dividend/transfer），持仓与现金变更随快照可追溯。
- **范围外**：配股、增发、缩股（罕见且数据复杂）。


### 6.7 策略模板与计划引擎
8 策略模板参数表同前端 v1 §8；调度看 `traders.status` 与计划 `schedule.frequency`，输出意图经 PlanEngine 约束过滤（scope→budget→position_rule→risk 四道闸）后才执行。条件单触发评估：`price_cross`（last 与阈值比较，单次触发防重复）、`pct_change`（当日相对昨收）、`time`（每交易日一次）、`ma_cross`（日K收盘口径）；止损/止盈以移动加权成本为基准，日亏损（已实现+浮亏）达 `daily_max_loss` → 计划转 paused + `risk_halt` 事件。

### 6.8 导出实现
CSV：UTF-8 with BOM；列 = §3.8 导出表；金额两位小数（机器友好，不加千分位）；流式生成。JSON：数组（`?stream=true` 可选 NDJSON）。区间过滤基于 `traded_at`/`created_at`/`date`；`positions`/`plans` 为当前时点快照。

### 6.9 指标计算
基于 `equity_snapshots` + `klines(sh000300)`；快照不足 2 日返回 null；年化因子 252；回撤期天数 = 谷底距峰顶交易日数；胜率取卖出成交。
