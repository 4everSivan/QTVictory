## 1. 产品概述与设计范围

QTVictory 是面向**量化交易系统的模拟底座**：以真实行情与真实交易规则构建 A 股实时前向仿真环境，供策略程序验证、对比与评估。本方案定义其 **Web 控制台（观察员控制台）** 的界面与交互基线。

**观察员控制台定位**：操作者是观察员（系统唯一管理员），控制台不持有任何独占能力——**UI 只是后端 API 的一个客户端**（API-first，见《02-后端设计方案》§4.1）。界面核心对象是**交易员**（任意数量、任意初始资金、手动/策略模式），顶栏"当前交易员"切换器决定持仓/委托/成交/收益分析与下单面板的作用对象。

**范围**：桌面工作台（≥1180px）单屏布局、单一主题皮肤（Nothing 深色，C004 收敛）、行情图表、下单与委托管理、交易员管理与排行、交易计划面板、数据导出入口。
**不在本版范围**：移动端适配、独立回测界面（回测引擎属后续系统）。

> 版本说明：v1 为原型已实现的样式基线定稿；**v2 对齐《02-后端设计方案》v3（观察员模型 / A 股规则级撮合 / API-first）**，标注 `〔v2 新增〕` 的组件尚未在原型实现，属升版设计。

**核心设计原则**（继承 Nothing 设计系统，v1 定稿不变）：做减法；单色灰阶即层级，红 `#D71921` 仅用于数据语义（涨）与买入主按钮；数据即美感（大号点阵/等宽数字）；机械感交互（透明度过渡，无弹跳）。

## 3. 样式基线（v1 定稿，v2 零变更）

### 3.1 主题体系
**双套系 + 三态切换**（C002，2026-09-18）：深色 = Nothing 纯黑基线（默认模式），浅色 = 明晰风套系（C002 接入）；顶栏操作区设主题按钮，点击按 **浅色 → 深色 → 跟随系统** 循环，模式持久化 localStorage `qtv_theme`（`light/dark/system`）；`system` 经 `prefers-color-scheme` 解析为 light/dark 并监听系统实时切换。CSS 令牌按 `:root`（默认深色）+ `:root[data-theme='light']` 分套，`data-theme` 写已解析主题；图表主题经 `initTheme()` 写入 `window.__THEME` 单一入口、订阅实时刷新。终端深蓝套系维持 C004 废弃决议，不在套系内。视觉语言重设计作为 future 储备另行立项，届时以新设计稿整体替换本节令牌。

## 6. 交易规则呈现（v2 重写：引擎归后端）

**v2 起前端不再内置撮合/账户引擎**（v1 的 `TRADE.*` 前端实现废止），后端《02》§6.1 为**唯一规则事实源**（A 股规则级：五档驱动市价单、量约束、部分成交、±2% 申报范围、集合竞价、板块申报单位、资金/持仓冻结、T+1、涨跌停、费用、公司行动）。

前端职责收窄为两层：
1. **输入层即时校验**（体验优化，非安全边界）：数量整百/科创板规则、价格区间（涨跌停 ± ±2%）、可用资金/可卖预估——最终以后端校验结果为准；
2. **后端错误码的 UI 呈现**：`LOT_SIZE / PRICE_BAND（details 含区间）/ INSUFFICIENT_FUNDS / T1_LOCKED / SESSION_CLOSED / STALE_QUOTE / PLAN_CONSTRAINT / RATE_LIMITED` 等映射为下单面板校验文案与 Toast（文案表在实现阶段随 OpenAPI 对齐）。

订单状态呈现：`wait → partial → filled | cancel`；`partial` 行内显示"已成交/委托量"进度。

## 7. 数据层（v2 重写：全部走后端 API）

### 7.1 架构
前端不再直连腾讯行情接口（v1 方案废止），**唯一数据源 = QTVictory 后端**（REST `http://127.0.0.1:8787/api` + WS `/ws`）。鉴权按后端配置透传 `X-API-Key`（私人部署默认免鉴权）。

### 7.2 UI 功能 ↔ 端点映射

| UI 区域 | REST（初始/兜底） | WS 订阅 |
|---|---|---|
| 自选列表/个股头部/盘口/图表 | `/market/quotes` `/market/kline` `/market/minute` | `quotes` |
| 顶栏指标/持仓/委托/成交/收益 | `/traders/{id}` 及从属端点 | `trader:{id}`、`traders` |
| 交易员侧板/详情/动态流 | `/traders` `/traders/events` `/templates` | `traders`、`events` |
| 计划面板 | `/traders/{id}/plans` `/plans/{id}/entries` | `plans` |
| 下单/撤单 | `POST/DELETE /traders/{id}/orders` | 回执经 `trader:{id}` |
| 导出 | `/traders/{id}/export`（浏览器下载） | — |

### 7.3 连接策略
启动顺序：REST 全量拉取渲染 → WS 订阅增量；断线重连后 REST 全量刷新再续订；WS 不可用时自动降级为 REST 轮询（quotes 3s / traders 5s）。行情降级状态（`source/live/fallback`）映射顶栏与盘口的状态徽标。

## 8. 交易员模块（v2 重写：展示层）

交易员调度、策略执行、计划触发全部在后端（02 §4.4/§6.7）；前端为纯展示 + 管理操作入口：
- **侧板排行**：`GET /traders` 按总收益率排序，manual/strategy 徽标，动态流最新一条；
- **创建**：模板列表（8 示例策略 + 参数 schema）来自 `GET /api/templates`，`POST /traders` 提交（含任意初始资金与可选计划）；
- **详情弹窗**：统计卡（后端 metrics）、真实净值曲线、持仓、最近成交、计划页签；
- v1 原型中的前端策略引擎（`traders.jsx` 的 ACT/调度）废止，其逻辑已由后端 Strategies 承接。

## 9. 状态管理与持久化（v2 重写）

**后端为唯一事实源**；前端状态分两类：
- **UI 态**（本地）：当前选中交易员 id、选中标的、Dock Tab、弹窗/面板开关——持久化仅限 UI 偏好（localStorage：上次选中交易员、主题模式 `qtv_theme`（`light/dark/system`，C002 三态切换））；
- **服务端状态缓存**：行情/交易员/计划/事件等，由 WS 增量维护、REST 初始化与兜底刷新；**不再写业务数据到 localStorage**（v1 的 `pt_sim_acct_v4` 账户持久化废止）。

组件拆分沿用 v1（panes/chart/traders/app），新增 `api/`（REST client + WS 订阅管理 + 错误码→文案映射）；生产迁移构建工具化后 `?v=` 缓存击穿随之消失。
