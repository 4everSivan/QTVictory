# 系统设计方案 (design/)

> **定位**: 系统现行基准事实源（Living Baseline / Source of Truth）
> **原则**: 全文始终反映当前代码库的完整规则与架构；不随单次 Bug 修复割裂，通过 [change/](../change/) 保持变更闭环。

---

## 1. 目录说明

`docs/devel/design/` 汇集了 QTVictory 系统级的前后端核心设计方案。所有业务规则、数据契约、领域模型与界面规约均以本目录下的文档为唯一事实依据。

## 3. 设计演进与变更纪律

1. **基线完整性**：设计方案保持“全文自洽”。读者无需查阅历史任务卡，通读设计方案即可掌握当前系统的全部业务与技术规则。
2. **变更追溯**：
   - 发生 Bug 修复或功能回调引起设计调整时，必须先在 [`docs/devel/change/`](../change/) 建立变更核验卡；
   - 在对应设计方案的“变更记录”中增补条目，并回链至对应的变更核验卡编号。
3. **关联文档**：
   - 架构决策的重大转折详见设计稿内 §6.13 对抗评审记录；
   - 阶段任务落实详见 [task/](../task/) 与 [plan/](../plan/)。
