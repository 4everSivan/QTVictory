## 2. 核心评估原则

1. **证据强制**：每一项评分必须锚定到具体的文件代码行号或命令输出，杜绝凭空主观打分；
2. **最小复跑包门槛**：后端 `pytest` 全量测试通过，前端 `vitest` + `tsc -b && vite build` 零报错作为硬性一票否决项；
3. **单一事实单一罚点**：防止同一违规在多个子维度重复扣分。

## 3. 文档生命周期与归档边界

按照 [docs/archive/README.md](../../archive/README.md) 规约，本目录文档严格实施“规则常驻、报告归档”边界管理：
- **评分规则（`01-评分标准.md`、`02-评分流程与证据清单.md` 及本 README）**：属于跨版本通用评分度量体系与执行规约，**常驻 `docs/devel/assessment/` 持续演进，不随版本 tag 归档**，后续评估轮次直接复用与增量修订；
- **评分报告（`03-评分报告.md` 及后续新增的轮次报告）**：记录特定版本开发线的逐项打分证据与最终评级快照，属于版本交付审计资产，**每次打出版本 tag 后物理迁移至 `docs/archive/<版本号>/assessment/` 只读封存**。
