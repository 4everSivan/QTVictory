## 1. 目录定位与生命周期原则

`docs/devel/todo/` 是项目未入轨事项的**轻量缓冲池（Backlog Intake Queue）**，实行**"只记待办，落地即移出，零历史沉淀"**的流转纪律：

```
                    ┌─────────────────────────┐
                    │      发现缺陷 / 灵感需求    │
                    └────────────┬────────────┘
                                 │
                                 ▼
                    ┌─────────────────────────┐
                    │    todo/ 对应版本登记     │
                    │      (表格化、待认领)     │
                    └────────────┬────────────┘
                                 │
                 ┌───────────────┴───────────────┐
                 ▼                               ▼
       【缺陷修复 / 微调回调】            【功能迭代 / 方案演进】
                 │                               │
                 ▼                               ▼
       docs/devel/change/               docs/devel/design/
       新建 C00x 变更核验卡             更新设计方案对应章节
                 │                               │
                 └───────────────┬───────────────┘
                                 │
                                 ▼
                    ┌─────────────────────────┐
                    │   ★ 从 todo/ 中物理移除  │
                    │   (历史由 change/design 承载)│
                    └─────────────────────────┘
```

### 核心流转红线
1. **入轨即移除**：只要该事项已经落入 `change/`（建了 C 卡）或 `design/`（完成了设计基线），就必须**立即从 `todo/` 表格中删去该行**，严禁在 `todo/` 中堆积 `[x]` 勾选项；
2. **多文件隔离**：不同版本与迭代范围由独立文件承载，支持多开发者/AI Agent 并行编辑，避免单一文件合并冲突；
3. **表格化纪律**：所有待办事项严格使用标准 Markdown 表格记录，列结构、编号与度量口径必须遵循本文 §3–§5 契约；
4. **行自含原则**：各行独立可懂，行与行之间**不互链、不引用其他行的 ID**（行是瞬态的，互链必然腐烂）；关联语境用单行文字自含说明，正式关联在落地文档（C 卡 / design 讨论稿）中建立双向回链。

## 2. 文件清单与版本映射

| 文件名 | 适用范围 | 包含表格 |
|---|---|---|
| [now.md](now.md) | 当前维护版本（版本号标注于文档头部） | 1. 待修复缺陷表 (Bugs)<br>2. 待复验与微调表 (Enhancements & Verification)<br>3. 当前版本功能迭代表 (Features，当前版本即做功能的立项登记) |
| [future.md](future.md) | 后续版本规划储备（常驻） | 1. 功能迭代储备表 (Features)<br>2. 技术债务与稳定性储备表 (Tech Debt)<br>3. 远期路线图 (Milestones) |

### 2.1 文件生命周期
1. 当前版本待办固定登记在 `now.md`，**文件名不随版本更名**；版本号标注于文档头部，并与 [CHANGELOG.md](../../../CHANGELOG.md) 最新条目保持一致；
2. 版本发布（打 tag）时：仅更新 `now.md` 头部版本字段，未落地行原位保留、继续轮转，编号延续不归零；
3. `future.md` 常驻，不随版本轮换；其中事项立项或落入 `design/` 后即移除；
4. 归属判断：修**当前维护版本**的问题登记进 `now.md`；**当前版本即做的功能**登记 `now.md` §3（FT 前缀编号规则同 future.md，立项建 M/T 卡后移出）；**下个版本及以后**才做的功能与债务登记进 `future.md`。

## 3. 编号规则（防冲突、可追溯）

1. **前缀语义**（受控枚举）：
   - `BG` —— 待修复缺陷（版本文件 · Bugs 表）
   - `EN` —— 待复验与体验微调（版本文件 · Enhancements 表）
   - `FT` —— 功能迭代储备（future.md · Features 表）
   - `TD` —— 技术债务与稳定性储备（future.md · Tech Debt 表）
2. **格式**：`前缀-四位序号`（例：`BG-0001`）；序号在每类前缀下**只增不复用**，删行不回收编号；
3. **计数器**：每个数据文件头部登记 `**下一编号**` 字段；新增行取该值，并随即把头部计数器 +1；
4. **迁移不改号**：版本轮换（§2.1）迁移行时保留原编号。

## 4. 度量口径（受控枚举）

- **严重度**（仅缺陷表 Bugs 使用）：
  `S1 阻断`（系统不可用 / 资金或数据错乱）｜ `S2 严重`（主流程受损、有绕行方案）｜ `S3 一般`（次要功能异常）｜ `S4 轻微`（体验与文案问题）
- **优先级**（其余各表使用）：
  `P0 立即`（安全 / 资金风险，放下一切处理）｜ `P1 本版本`｜ `P2 下版本`｜ `P3 愿景`
- 缺陷表严禁填优先级，其余表严禁填严重度；枚举值纯净，禁止括号小尾巴（写入"来源/备注"列）。

## 5. 标准表模板

拟流转目标为受控枚举：`change (BugFix/Rollback/Refactor/Param)` ｜ `design` ｜ `plan/task` ｜ `report/test`。

**缺陷表（版本文件）**：
```markdown
| ID | 模块 | 缺陷现象与复现线索 | 严重度 | 登记日期 | 拟流转目标 | 来源/备注 |
|---|---|---|---|---|---|---|
| BG-0001 | 模块名 | 现象、复现步骤或线索 | S1/S2/S3/S4 | YYYY-MM-DD | change (BugFix) | 附加说明 |
```

**待复验与微调表（版本文件）**：
```markdown
| ID | 模块 | 事项描述 | 优先级 | 登记日期 | 拟流转目标 | 来源/备注 |
|---|---|---|---|---|---|---|
| EN-0001 | 模块名 | 复验步骤或微调内容 | P0/P1/P2/P3 | YYYY-MM-DD | change (Param) | 附加说明 |
```

**功能迭代储备表（future.md）**：
```markdown
| ID | 模块/标的 | 需求概述与核心语义 | 优先级 | 登记日期 | 拟落地方向 | 来源/参考 |
|---|---|---|---|---|---|---|
| FT-0001 | 模块名 | 需求方向与核心语义（不写实现细节） | P0/P1/P2/P3 | YYYY-MM-DD | design 01 §X | 来源链接 |
```

**技术债务储备表（future.md）**：
```markdown
| ID | 模块 | 债务/优化点 | 优先级 | 登记日期 | 拟落地方向 | 来源/备注 |
|---|---|---|---|---|---|---|
| TD-0001 | 模块名 | 债务描述与影响 | P0/P1/P2/P3 | YYYY-MM-DD | change / test | 附加说明 |
```

**当前版本功能迭代表（now.md §3，列结构与拟流转目标受控枚举同功能迭代储备表）**：
```markdown
| ID | 模块/标的 | 需求概述与核心语义（不写实现细节） | 优先级 | 登记日期 | 拟流转目标 | 来源/参考 |
|---|---|---|---|---|---|---|
| FT-0009 | 模块名 | 需求方向与核心语义 | P0/P1/P2/P3 | YYYY-MM-DD | plan/task | 来源链接 |
```

**空表占位行**：表格无待处理项时，保留唯一占位行——
```markdown
| *(当前无待处理项)* | - | - | - | - | - | 发现新事项在此增补行 |
```
