## 1. 变更背景与动因

EN-0006 登记（2026-09-17 本机实测）：腾讯快照域 https 断、东财 push2 http/https 全断——现行三级降级链（腾讯 https → 东财 → 内置锚点）在本机环境**首末两级同时失效**，行情全灭直接构成 EN-0001（撮合成交全链路复验）的堵点根因。

2026-09-18 复测留证（curl，`-m 6`）：

| 端点 | 结果 |
|---|---|
| `https://qt.gtimg.cn/q=`（腾讯快照） | ❌ 超时（exit 28，6.0s） |
| `http://qt.gtimg.cn/q=`（腾讯快照） | ✅ 200（53ms，GBK 响应格式与 https 完全一致） |
| `https://hq.sinajs.cn/list=`（新浪，无 Referer） | ❌ 403（5.2s） |
| `https://hq.sinajs.cn/list=`（新浪，带 `Referer: https://finance.sina.com.cn`） | ✅ 200（77ms） |
| `https://push2.eastmoney.com/api/qt/stock/get`（东财快照） | ❌ 空回复（exit 52） |
| `https://web.ifzq.gtimg.cn/appstock/app/fqkline/get`（腾讯 ifzq K线） | ✅ 200 |
| `https://push2his.eastmoney.com/api/qt/stock/kline/get`（东财 push2his K线） | ⚠️ 间歇可达（首测 200，复测 SSL EOF 断连，与 push2 同症状） |

适配器级真机复验（2026-09-18 11:17，`local/c008_live_check.py`，真实 httpx 请求）：
1. 腾讯 `fetch_quotes`：https 超时后自动落 http，返回快照含五档（sh600519 last=1257.10、bids/asks 正常）——协议兜底生效；
2. 新浪 `fetch_quotes`（https + Referer）：与腾讯同秒口径对齐（last/昨收/五档一致，cum 1133773 ↔ 1133800 股为采样时差；成交额 142934.85 万）——字段映射正确；
3. 腾讯 ifzq `fetch_daily_klines`（https 主源）：稳定返回 7 元组日K（含当日未收盘实时 K）；
4. 东财 push2his `fetch_daily_klines`：本机间歇可达（成功时 200、失败时 SSL EOF），作为异地环境兜底保留，本机链路实际兜底主力为 新浪（快照）+ 腾讯 http（快照）+ 腾讯 ifzq https（K线）。

服务级实测（测试环境 8788，按 [deployment-report.md](../../../local/deployment-report.md) 维护命令重启加载新代码，2026-09-18 11:25）：
- **BEFORE**（旧代码实例，09:41 部署自 a259956）：`GET /api/session` → `{"state":"degraded","phase":"continuous"}`；`GET /api/market/quotes` → `source=anchor, live=false`（锚点静态快照，无五档无量）——EN-0006 堵点现场；
- **AFTER**（C008 代码重启后）：`state=trading`、`source=tencent, live=true`，沪深300 实时快照（last/prevClose/open/high/low 连贯，11:26 盘中），日K 引导端点正常返回——https 超时自动落 http 的协议兜底在真实服务闭环生效。

结论：① 同源快照域 https 断但 http 通，协议级兜底可行；② 新浪 https 加 Referer 头即通，且自带五档与当日累计量（质量与主源同级，字段口径实测对齐腾讯）；③ 东财快照域不可达、push2his 间歇可达，保留为异地环境末级兜底。

## 2. 规则与设计变更对照（人工核验重点）

| 维度 | 变更前（旧逻辑） | 变更后（新逻辑） | 取舍理由与影响边界 |
|---|---|---|---|
| **快照降级链** | 腾讯 https → 东财 → 内置锚点（连续 3 败熔断切换） | 腾讯 https → 腾讯 http（同解析器仅换协议，适配器内自动兜底）→ 新浪 https（需 Referer 头）→ 东财 → 内置锚点；3 败熔断阈值与 60s 锚点闭锁不变 | 本机实测腾讯 https 与东财快照同时失效；协议兜底与同质备源优先于异构备源。腾讯 http 档不单列 source（仍报 `tencent`，避免透出枚举膨胀） |
| **source 透出枚举** | `tencent` ｜ `eastmoney` ｜ `anchor` | `tencent` ｜ `sina` ｜ `eastmoney` ｜ `anchor`（前端 `types.ts` 联合类型同步） | 新浪档数据完整，需独立透出供前端质量标识 |
| **降级档撮合语义** | 非 tencent 即 degraded（无增量量，撮合回落 `fill_model=fallback`） | 仅 `eastmoney`/`anchor` 为 degraded；`sina` 与 `tencent` 同为完整档（有五档与 ΔV 差分增量量） | 新浪自带五档与当日累计量，量纲均为股、与归一后口径一致（实测：腾讯 9571 手 ↔ 新浪 957073 股，同秒采样偏差 <0.01%） |
| **日K 引导兜底** | 仅腾讯 ifzq https，失败仅记日志静默 | 腾讯 ifzq https → 东财 push2his（前复权日K，量纲：手，与腾讯 ifzq 一致，7 元组契约不变） | 快照域曾整域故障，K线同源风险不为零；push2his 本机实测可达。腾讯 ifzq http 为 302 跳转（httpx 默认不跟随），不纳入兜底 |
| **快照解析** | 仅腾讯 GBK `~` 分隔字段位映射 | 新增新浪 GBK 逗号分隔解析（纯函数）：字段 0 名称 ｜ 1 今开 ｜ 2 昨收 ｜ 3 现价 ｜ 4 最高 ｜ 5 最低 ｜ 8 成交量(股) ｜ 9 成交额(元，÷10000 归一为万) ｜ 10–29 五档（量/价交替，量纲：股）｜ 30 日期 ｜ 31 时间 | 新浪无停牌专用位，沿用"现价≤0 且今开≤0 判停牌"口径；指数无盘口（字段为 0）按价量非正自然跳过 |
| **回滚方式** | - | 还原 `market.py` 降级链与 `tencent.py`/`fallback.py`/`types.ts` 改动即回到三级链；新增 `sina.py` 独立成文件，回滚无需删除（无引用即死代码） | 变更不触碰库结构与撮合内核，回滚面收敛在 4 个源文件 + 1 个新适配器 |
| **明确不做** | - | 百度股市通备源接入、交易所/巨潮交易日历与公司行动源接入、分钟历史回补 | 评估后搁置：现链已有三层网络兜底 + 锚点；交易日历由快照时间戳推定的现行口径不变；公司行动维持 corporate_actions 表直写钩子（02 §3.4 已标注边界）。easyquotation/akshare 仅作字段口径参考，不入运行时依赖 |

## 3. 代码变更与受影响文件

- 新增适配器：`backend/app/adapters/sina.py`（`SinaAdapter` + `parse_sina_payload` 纯函数，Referer 头注入）
- 腾讯协议兜底：`backend/app/adapters/tencent.py`（`QUOTE_URL_HTTP`；`fetch_quotes` https 失败自动降 http，同一解析器）
- 东财 K线：`backend/app/adapters/fallback.py`（`EastmoneyAdapter.fetch_daily_klines`，push2his 前复权日K）
- 降级链重构：`backend/app/services/market.py`（`poll_once` 备源链 [新浪 → 东财]；`_ingest` 完整档判定 `source not in ("tencent", "sina")`；`_bootstrap_klines` 双源兜底）
- 前端契约：`frontend/src/api/types.ts`（source 联合类型增 `sina`；`quoteQuality` 完整档集合 `{tencent, sina}`）
- 测试覆盖：`backend/tests/service/test_market.py`（新浪解析五档/指数空盘口/停牌/成交额归一、降级链次序与 degraded 语义、K线引导兜底）
