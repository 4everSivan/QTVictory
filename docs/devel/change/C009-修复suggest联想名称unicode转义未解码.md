# C009 - 修复 suggest 联想名称 unicode 转义未解码

> **卡片ID**: C009 ｜ **类型**: BugFix ｜ **状态**: 核验通过
> **创建日期**: 2026-09-18 ｜ **关联设计**: [02-后端设计方案.md](../design/02-后端设计方案.md) §3.10（名称联想）、§5.2（`/market/suggest` 行）

---

## 1. 变更背景与动因

M17/T24 前端联调实测发现：`GET /api/market/suggest?q=` 返回的 `name` 字段为字面 `\uXXXX` 转义文本（如"中国平安"返回为 `\u4e2d\u56fd...` 字符序列），联想下拉名称栏不可读。

**根因**：腾讯 smartbox v2 hint 串中名称字段以 ASCII `\uXXXX` 转义序列承载中文，`backend/app/adapters/tencent.py` `parse_suggest_payload()` 直接取 `fields[2]` 原文透传，未做反转义。快照/日K 路径不受影响（行情接口响应为 GBK 直编码中文，实测"贵州茅台/招商银行"名称正确）。

该缺陷属 T23 新引入代码（suggest 代理为 v6 新增端点），非 Phase 1 遗留。缺陷导致 T24 E2E 联想断言降级为结构契约（前缀码 + 类别），名称正确性无法验收——非修不可。

## 2. 规则与设计变更对照（人工核验重点）

| 维度 | 变更前（旧逻辑） | 变更后（新逻辑） | 取舍理由与影响边界 |
|---|---|---|---|
| **接口契约** | `/market/suggest` 响应 `name` 为字面 `\uXXXX` 转义文本 | `name` 为解码后的 Unicode 中文 | 恢复 02 §3.10 设计语义（规范化 `{code, name, kind}`）；契约形状不变，仅字段内容修正 |
| **错误处理/异常流** | 不变 | 不变 | 无 |
| **代码逻辑** | `parse_suggest_payload` 透传 `fields[2]` | 名称字段经 `\uXXXX` 正则反转义；无转义的直编码中文原样通过 | 纯增量解码，不影响已正常的中文直编码路径 |

## 3. 代码变更与受影响文件

- 核心实现：`backend/app/adapters/tencent.py`（`parse_suggest_payload` 名称字段反转义）
- 测试覆盖：`backend/tests/service/test_watchlist.py`（TestSuggest 增补转义载荷用例）；`frontend/scripts/e2e.mjs`（T24 段联想断言由结构契约恢复为含中文名称断言）
